# data/ — входные файлы справочников

Здесь лежат файлы, из которых приложение наполняет справочники. Они
**не шаблоны** договоров (те — в `templates/`), а данные.

## `spravochnik_mest_vygruzki.xlsx` — справочник мест выгрузки (салоны)

Файл из 192 записей: площадки, куда возят автомобили. Из него наполняется
справочник выгрузки (`address_book.point_type = 'unloading'`) при **первом
запуске** приложения — если справочник выгрузки пуст
(`db/database.py::_load_salons_if_empty`).

Графы (ищутся **по заголовкам**, порядок может быть любым):

| Графа | Куда идёт |
|---|---|
| КОД | `salon_code` — код салона, например `JMR-A048` |
| ИНН | `salon_inn` |
| Юр. Лицо | `salon_name` — наименование грузополучателя |
| Город | `salon_city` |
| Адрес доставки автомобилей | `address` — адрес выгрузки |
| остальные (№, КПП, юридический адрес, комментарии) | не читаются |

Правила разбора — `db/database.py::read_salons_rows`. Импорт вручную (кнопка
«Импорт из Excel» в справочнике) читает **тот же** формат.

### Почему это не оригинал файла заказчика

В оригинале «Места выгрузок.xlsx» есть графы с персональными данными:
e-mail получателей уведомлений, контактные телефоны (в том числе приёмщиков)
и ФИО региональных менеджеров. По `AGENTS.md` § 4 такие данные в git не
коммитятся, поэтому:

* в проект идёт **санитизированная** копия — только деловые графы
  (код, ИНН, юр. лицо, город, юридический адрес, адрес доставки, график);
* оригинал хранится локально в `data/private/` и закрыт `.gitignore`;
* пересобрать файл проекта из оригинала:
  `python tools/make_salons_reference.py`.

Если файла проекта нет, приложение работает как обычно — справочник
наполняется вручную или импортом из Excel.
