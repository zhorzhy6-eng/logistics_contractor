# PRIVATE_MIGRATION — разделение проекта на публичную и приватную части

> Дорожная карта и инструкция. Файл ведёт агент, пользователь может править.
> Обновлено: 2026-10-15. Шаг: разделение проекта (см. `docs/STATE.md`).

## 1. Зачем разделение

Проект готовит договоры по нескольким типам. Часть типов — **клиентские**:
их шаблоны, промпты распознавания и окна ввода содержат коммерческую
инклиентского типа A (названия заказчиков, реквизиты, условия). Публичный репозиторий
такой инклиентского типа A содержать не должен — ни в рабочем дереве, ни в истории.

Публичная часть (ядро) — это тип «Экспедиторство»: общий движок генерации,
распознавание, база, агент Максимилиан, UI-каркас. Она самодостаточна:
программа запускается и работает без приватной части.

## 2. Две части

| | Публичная | Приватная |
|---|---|---|
| Папка | `E:\Programmy\logistics_contractor` | `E:\Programmy\logistics_contractor_private` |
| Репозиторий | `github.com/zhorzhy6-eng/logistics_contractor` | `github.com/zhorzhy6-eng/logistics_contractor_private` |
| Типы | «Экспедиторство» (`perevozka`), служебный `expediciya` | клиентские типы (остальные) |
| Шаблоны | `shablon_ooo.docx`, `shablon_ip_with_vat.docx`, `shablon_ip_without_vat.docx` | все остальные бланки и образцы |

## 3. Как программа находит приватную часть

Единственная точка входа — `core/private_path.py`:

```python
from core.private_path import attach_private_root
attach_private_root()
```

Вызов стоит **до** первого импорта `core.*` в `main.py` и в
`tests/conftest.py`. Что делает `attach_private_root()`:

1. ищет приватную папку: переменная окружения `LOGISTICS_PRIVATE_ROOT`
   (если задана — ищется ровно она), иначе `E:\Programmy\logistics_contractor_private`,
   `~/logistics_contractor_private`, `<публичный корень>/private`;
2. добавляет найденный корень в начало `sys.path`;
3. расширяет `__path__` пакетов `core`, `core.agent`, `core.contracts`,
   `core.prompts`, `ui`, `ui.windows`, `tools`:
   * уже импортированных — сразу;
   * импортируемых позже — перехватчиком импорта в `sys.meta_path`.

Третий пункт обязателен, и это главная грабля: обычный пакет (`core`,
`ui`) «выигрывает» поиск у одноимённой папки на `sys.path`, поэтому без
расширения `__path__` подпакеты клиентских типов не находятся. Публичный
`core/contracts` при этом объявлен **пакетом-пространством имён** (у него
нет `__init__.py`) — так публичные и приватные подпакеты живут рядом.

Приватной папки нет — программа работает в режиме ядра: в списке выбора
остаётся «Экспедиторство». Ошибок при этом нет: реестр
(`core/contracts/registry.py`) изолирует сбой импорта каждого типа,
промпты возвращают `None`, список строится только по зарегистрированным
типам.

Переопределить расположение приватной папки можно переменной окружения:

```powershell
$env:LOGISTICS_PRIVATE_ROOT = "D:\private\logistics_contractor_private"
```

## 4. Что где лежит

Приватная папка повторяет структуру публичной, чтобы импорты
(`core.contracts.<ключ>`, `ui.windows.<ключ>`) работали без правок:

```
logistics_contractor_private/
├── core/
│   ├── agent/labels.py       # названия типов и обязательные поля для агента
│   ├── contracts/            # генератор, валидатор, постобработка типов
│   │   └── picker_labels.py  # человекочитаемые названия типов для списка
│   ├── prompts/              # промпты распознавания (имя модуля = ключ типа)
│   └── mirror_targets.py     # карты зеркала «Экспедиторство → тип»
├── ui/windows/               # окна типов и их вкладки
├── templates/                # бланки и образцы клиентов + три бланка Экспедиторства
├── data/knowledge/tutorial/  # инструкции оператора по клиентским типам
├── tools/                    # сборка бланков и сценарии золотых эталонов
└── tests/                    # тесты клиентских типов
```

Шаблоны лежат в привате **только** в `<приватный корень>/templates`:
публичный код передаёт генератору один и тот же `templates_dir`, а имена
файлов бланков у типов не пересекаются (три бланка «Экспедиторства»
продублированы в приватной папке, чтобы папка была полной).

## 5. Как добавить нового клиента

1. Создать в приватной папке подпакеты: `core/contracts/<ключ>/`
   (`__init__.py`, `generator.py`, `validator.py`, `postprocess.py`)
   и `ui/windows/<ключ>/` (`window.py`, `data.py`, `tabs/`).
2. В `core/contracts/<ключ>/__init__.py` зарегистрировать тип:

   ```python
   from core.contracts.registry import register_contract_type

   register_contract_type(
       "<ключ>", "Название для оператора",
       generator_class=MyGenerator, validator_class=MyValidator,
   )
   ```

3. Добавить ключ в публичный `core/contracts/registry.py`
   (`BUILTIN_TYPE_MODULES` и `OPTIONAL_TYPE_MODULES`) — реестр подхватит
   модуль, если приватная часть подключена, и просто пропустит его, если нет.
4. Добавить название в приватный `core/contracts/picker_labels.py`
   (`PICKER_LABELS`) и ключ — в публичный `core/contracts/picker_order.py`
   (`PICKER_KEYS`).
5. Положить бланки в приватный `templates/`, промпт — в приватный
   `core/prompts/<ключ>.py` (имя файла = ключ типа), инструкцию — в приватный
   `data/knowledge/tutorial/<ключ>.md`.
6. Добавить окно в фабрики `main.py` (`_TYPE_WINDOW_MODULES`).
7. Написать тесты в приватной `tests/` и запустить их оттуда.

## 6. Правила

1. **Ничего с названиями клиентов — в публичный репозиторий.** Ни в файлы,
   ни в имена файлов, ни в сообщения коммитов.
2. Новый клиент — его файлы идут **только** в приватную папку.
3. База данных, логи, ключи API — **никогда** в git: ни в публичном,
   ни в приватном.
4. Перед коммитом в публичную репу — проверка:

   ```powershell
   git grep -n -i "клиентского типа A\|клиента B\|клиент B\|клиентского типа C\|клиента B"
   ```

   Команда должна молчать.
5. Правки публичного ядра не должны требовать правок приватной части,
   и наоборот: связь — только через реестр типов, `picker_order`,
   `picker_labels`, `mirror_targets` и `core/agent/labels.py`.

## 7. Тесты

* Публичные тесты запускаются как обычно:

  ```powershell
  pytest -q -o addopts="" --basetemp=tests/_tmp/_pt
  ```

  `pytest.ini` не собирает приватную папку (`norecursedirs`), а `conftest.py`
  подключает её путь — тесты ядра, которым нужны клиентские типы, работают,
  когда приватная часть есть на диске. Без неё они пропускаются маркером
  `needs_private` с понятной причиной.
* Приватные тесты запускаются из приватной папки (её `tests/conftest.py`
  сам добавляет в `sys.path` и приватный корень, и публичное ядро —
  переменная `LOGISTICS_PUBLIC_ROOT` или папка рядом).
