# Правовая база pravo.gov.ru

Локальная база нормативных актов для перевозчика: скачивание с
официального портала правовой информации, извлечение текста и подготовка
к поиску. Документ описывает **этап 1 — парсер**; RAG-индексация
(этап 2) описана в разделе «RAG» ниже и в `core/agent/rag.py`.

---

## 1. Что где лежит

| Что | Где |
|---|---|
| Список источников | `config/legal_sources.json` |
| Парсер | `core/legal_parser.py` |
| Метаданные документов | `db/legal_metadata.db` (модуль `db/crud/legal_metadata.py`) |
| Фрагменты и эмбеддинги (RAG) | `db/legal_metadata.db` (модуль `db/crud/knowledge.py`) |
| Оригиналы (PDF, HTML) | `data/knowledge/legal/original/` |
| Извлечённый текст (TXT, UTF-8) | `data/knowledge/legal/text/` |
| Кэш обращений к порталу | `data/knowledge/legal/cache/` |
| Скачивание из командной строки | `tools/download_legal.py` |
| Мониторинг обновлений | `tools/update_legal.py` |
| Диалог «Правовая база» | `ui/legal_base_dialog.py` |
| Раздел настроек | `ui/legal_settings.py` |

Скачанные документы **в git не хранятся** (`data/knowledge/legal/.gitignore`):
это десятки мегабайт PDF-сканов, они свободно доступны на портале и
восстанавливаются одной командой `python tools/download_legal.py --all`.

## 2. Источник: какие каналы портала используются

Портал даёт два независимых канала, и оба задействованы — потому что
у каждого свои сильные стороны.

### 2.1. REST-API портала опубликования

`http://publication.pravo.gov.ru/api` — тот же интерфейс, которым
пользуется веб-страница портала.

| Запрос | Что даёт |
|---|---|
| `GET /Documents?pageSize=100&index=N` | страница ленты опубликования |
| `name=`, `number=` | фильтры по названию и номеру акта |
| `DocumentTypes=<GUID>` | вид документа (Федеральный закон, Постановление, Приказ…) |
| `SortedBy=1` | от старых к новым (по умолчанию — от новых) |
| `GET /DocumentTypes` | справочник видов документов |
| `GET /SignatoryAuthorities` | справочник органов, подписавших акт |
| `GET /file/pdf/<номер опубликования>` | сам документ (PDF) |

Ограничения, проверенные на живом портале:

* `pageSize` — значение **перечислением**: принимаются только `10`, `30`,
  `100`, остальное даёт `400`;
* фильтра по дате в API **нет** — период отбирается на клиенте
  (лента идёт от новых к старым, поэтому обход прекращается на первом
  документе старше порога);
* оригинала акта на портале нет, если он опубликован **до 2011 года**
  (портал ведётся с этого времени).

### 2.2. Банк «Законодательство России»

`http://pravo.gov.ru/proxy/ips/?doc_itself=&nd=<идентификатор>` — отдаёт
**консолидированный текст** акта в HTML (CP1251). Это единственный канал
портала, где у документов есть текстовый слой, поэтому кодексы берутся
отсюда: например, ГК РФ часть вторая приходит целиком, вместе с главой 40
«Перевозка» и главой 41 «Транспортная экспедиция».

Идентификатор `nd` в банке **не выводится из номера акта** — он задаётся
в `config/legal_sources.json` явно, для каждой записи отдельно.

### 2.3. Почему поиск в банке не используется

У банка «Законодательство России» поиск устроен как набор фреймов,
которыми управляет JavaScript: серверный ответ на поисковый запрос —
всегда одна и та же страница формы, а список результатов подгружает
скрипт. Проверено на живом портале: параметры `a0` (контекст),
`intelsearch`, `searchres`, `find`, `start_search`, `list` с корректной
кодировкой CP1251 и с сессионной кукой — сервер их игнорирует и
возвращает форму (14 2593 байта независимо от запроса). Воспроизводить
это без браузера — значит строить парсер на костылях, поэтому поиск идёт
через REST-API (п. 2.1), а банк используется только как хранилище текста
по известному `nd`.

## 3. Откуда берётся текст: почему нужен OCR

PDF на портале опубликования — **отсканированные страницы без текстового
слоя**. Проверено на семи актах:

| Акт | Страниц | Символов текстового слоя |
|---|---|---|
| Постановление № 2200 | 48 | 0 |
| Постановление № 1640 | 20 | 0 |
| Постановление № 1642 | 54 | 0 |
| Постановление № 1639 | 10 | 0 |
| Приказ Минтранса № 368 | 4 | 0 |
| Приказ Минтранса № 141 | 5 | 0 |
| Приказ Минтранса № 440 | 47 | 0 |

Поэтому извлечение текста идёт в два шага:

1. читается текстовый слой (движок `pypdfium2` — он объявлен в
   `requirements.txt`; запасной вариант — `pypdf`);
2. если текста меньше порога (`ocr_min_chars`, по умолчанию 200 символов),
   страницы рендерятся в 300 dpi и распознаются локальным
   **Tesseract** (`rus+eng`).

Замер на этой машине: **1,5 с на страницу**, качество русского текста
достаточное для поиска. 48 страниц постановления № 2200 дали 78 305
символов текста.

Если Tesseract не установлен, документ **всё равно скачивается**, но
`text_chars` остаётся нулём, а причина пишется в `extra['last_error']` —
база не притворяется полной.

Поддерживаемые форматы: PDF, HTML/HTM, TXT, RTF (разбирается своим
кодом, без зависимости `striprtf`), DOCX, ZIP (внутри архива выбирается
самый пригодный файл).

## 4. Список источников

`config/legal_sources.json` — единственное место, где перечислены акты.
Формат записи:

```json
{
  "id": "pp_2200",
  "short": "ПП № 2200",
  "title": "Постановление Правительства РФ от 21.12.2020 № 2200 …",
  "number": "2200",
  "date": "2020-12-21",
  "doc_type": "Постановление",
  "eo": "0001202012230048",
  "nd": "",
  "query": "Об утверждении Правил перевозок грузов автомобильным транспортом",
  "topics": ["перевозка грузов", "транспортная накладная"],
  "required": true
}
```

Порядок разрешения записи:

1. `nd` — текст берётся из банка «Законодательство России»;
2. `eo` — файл берётся с портала опубликования, метаданные — из списка;
3. `query` — документ ищется на портале, и результат принимается **только
   при совпадении названия**: номер без подтверждения датой или названием
   не считается совпадением (номеров вида «259-ФЗ» на портале десятки, по
   одному на каждый год);
4. `"unavailable": true` — акт опубликован до 2011 года, в открытом
   доступе портала его нет. Такой документ попадает в базу как «ручной»:
   файл для него кладёт оператор, и индекс его подхватывает.

### Категории

| Категория | Что внутри |
|---|---|
| `codes` | ГК РФ ч. 1 и ч. 2 (главы 40, 41), НК РФ ч. 1 и ч. 2, КоАП РФ |
| `federal_laws` | ФЗ-259 (Устав автомобильного транспорта), ФЗ-16 (О транспортной безопасности) |
| `government_decrees` | Правила перевозок грузов (№ 2200), № 1640, № 1642, № 1639 |
| `ministry_orders` | путевые листы (№ 368), предрейсовый контроль (№ 141), тахографы (№ 440), № 476, № 285, № 343 |
| `regional` | пример регионального акта о тарификации |

Ключевые слова (`keywords`) используются мониторингом обновлений:
«перевозка грузов», «транспортная экспедиция», «автомобильный транспорт»,
«транспортная безопасность», «путевой лист», «тахограф», «транспортная
накладная», «предрейсовый контроль», «ответственность перевозчика»,
«просрочка доставки груза».

## 5. Как пользоваться

### Скачать базу целиком

```
python tools/download_legal.py --all
```

### Частично

```
python tools/download_legal.py --category ministry_orders
python tools/download_legal.py --only-required
python tools/download_legal.py --search "путевой лист" --limit 5
python tools/download_legal.py --url 0001202012230048
python tools/download_legal.py --no-ocr          # только файлы, быстро
python tools/download_legal.py --stats
```

### Следить за обновлениями

```
python tools/update_legal.py                      # что нового за 30 дней
python tools/update_legal.py --days 7 --download  # за неделю и сразу скачать
python tools/update_legal.py --watch "тахограф" --days 365
python tools/update_legal.py --status
```

### Из программы

Меню правовой базы открывает диалог `ui/legal_base_dialog.py`: список
документов, дата последнего обновления, размер базы, кнопки
**[Обновить всё]**, **[Скачать документ]**, **[Скачать категорию]**,
**[Проверить обновления]**, **[Открыть папку]**.

Раздел настроек `ui/legal_settings.py` — готовый виджет
`LegalSettingsSection`: его достаточно вставить в окно настроек одной
строкой. Настройки хранятся в `config/settings.json` в разделе `legal`:

```json
{
  "legal": {
    "enabled": true,
    "auto_index": false,
    "top_k": 5,
    "chunk_size": 900,
    "chunk_overlap": 100,
    "embedding_model": "Embeddings",
    "lexical_fallback": true
  }
}
```

### Из кода

```python
from core.legal_parser import LegalParser

parser = LegalParser()
docs = parser.search("перевозка грузов", doc_type="Федеральный закон", limit=5)
parser.download(docs[0].id)
parser.download_all(category="government_decrees")
parser.list_updates("2026-01-01")
parser.stats()
```

## 6. База метаданных

`db/legal_metadata.db`, таблица `legal_documents`:

| Колонка | Смысл |
|---|---|
| `id` | стабильный ключ: `eo:<номер опубликования>`, `nd:<идентификатор>`, `cfg:<id из списка>` |
| `eo_number`, `nd` | номера в двух каналах портала |
| `title`, `short_title`, `number`, `doc_date`, `publish_date` | реквизиты акта |
| `authority`, `doc_type`, `category`, `source` | орган, вид, категория, источник |
| `url`, `file_url` | страница документа и адрес файла |
| `original_path`, `text_path`, `text_chars` | что скачано и сколько текста |
| `checksum` | SHA-256 оригинала |
| `ocr_used` | текст получен распознаванием |
| `downloaded_at`, `updated_at` | когда скачано и обновлено |
| `extra` | JSON: темы, число страниц, причина последней ошибки |

Повторное сохранение **не затирает** уже известные значения: проход
парсера без текста не стирает скачанный ранее файл.

Отдельный файл базы (а не `contracts.db`) выбран сознательно: правовая
база — справочник, её можно удалить и пересобрать, не тронув ни одного
договора. По той же причине её схема не идёт через `db/schema.py` и
`db/migrations.py`.

## 7. Ограничения и что делать с пробелами

| Ограничение | Что это значит на практике |
|---|---|
| Акты до 2011 года на портале отсутствуют | УАТ (ФЗ-259), ФЗ-16, НК РФ, КоАП РФ помечены `"unavailable": true`. Ответственность за просрочку доставки груза на этот период закрывается главой 40 ГК РФ (ст. 793–796) — она в базе есть |
| PDF портала — сканы | Текст появляется только после OCR; без Tesseract `text_chars = 0` |
| Ошибки OCR возможны | В номерах статей и цифрах распознавание может ошибиться; для юридически значимых цитат первоисточник — PDF в `original/` |
| Портал может быть недоступен | Парсер делает 3 попытки, затем пишет причину в отчёт и в `extra['last_error']`; скачанные ранее файлы остаются на месте |
| Изменения акта приходят отдельными документами | Список источников хранит основные акты; изменения собираются `tools/update_legal.py` |

Добавить документ вручную: положите файл (PDF, HTML, TXT, RTF, DOCX) в
`data/knowledge/legal/original/` — индекс этапа 2 читает папку целиком и
подхватит его без правки списка источников.

## 8. Тесты

`tests/test_legal_parser.py` — 81 тест, **все на MOCK**: сеть не
трогается ни одним запросом. Парсер принимает готовую `requests.Session`,
поэтому вместо неё подставляется `FakeSession` с заранее описанными
ответами портала.

```
pytest tests/test_legal_parser.py -o addopts="" -q --basetemp=tests/_tmp/_pt_legal
```

Что покрыто: список источников, разбор дат и имён файлов, HTML/RTF/ZIP/TXT,
клиенты обоих каналов портала (включая кодировку CP1251, повторы при 503
и отсутствие повторов при 400), поиск и отбор документов, правило «номер
без даты и названия не совпадение», мониторинг обновлений, база метаданных
(upsert без затирания, статистика, поиск по кириллице), скачивание обоих
типов, массовое скачивание с пропуском уже скачанных, интерфейс
(offscreen).

## 9. Правовая сторона

Источник — официальный интернет-портал правовой информации
`pravo.gov.ru`, открытые данные. Скачивание не требует регистрации и не
нарушает прав: акты органов власти не являются объектами авторских прав
(ст. 1259 ГК РФ, п. 6). Парсер обращается к порталу с паузами между
повторами и представляет себя в `User-Agent` осмысленным именем.

## 10. Что не сделано (отдельным шагом)

* **Интеграция с Максимилианом** — инструменты `search_legal(query)` и
  `download_legal(query)`, правки промпта `core/agent/prompts/maximilian.txt`,
  кнопка в настройках агента. Требует правки
  `ui/agent_settings_dialog.py`, `core/agent/tools.py` и промпта —
  эти файлы ведёт другой разработчик, в этом шаге они не тронуты.
* **Автоматическое обновление по расписанию** — сейчас мониторинг
  запускается вручную (`tools/update_legal.py` или кнопка в диалоге).
