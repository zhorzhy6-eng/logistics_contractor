**Предыдущий шаг — ключ GigaChat: формат проверяется до сети.** 02.11.2026 распознавание падало с «Ошибка авторизации GigaChat: 400 {"code":4,"message":"Can't decode 'Authorization' header"}». Причина — не код, а данные: в системном хранилище лежал ключ `sk-…` (так выглядят ключи OpenAI-совместимых сервисов), а GigaChat ждёт «Authorization key» — Base64 от пары client_id:client_secret. Программа приняла его молча (set_key.py проверял только длину и ASCII) и узнала о подмене на первом запросе токена.
1. `infrastructure/secrets/store.py` — одно правило формата на всё приложение: `normalize_gigachat_key`, `gigachat_key_problem` (причина словами, без значения), `gigachat_key_error_text`, `INVALID_GIGACHAT_KEY_MESSAGE`.
2. `set_gigachat_key` отвергает такой ключ (`ValueError`) — консоль, окно и сторонние скрипты идут через него.
3. `GigaChatClient._get_token` проверяет формат ДО сети → понятный текст, ноль обращений к сервису; 400 от сервиса тоже объясняется словами. `key_problem()` — публичный ответ «что не так с ключом».
4. `set_key.py` больше не спрашивает «всё равно сохранить?»: отказ с инструкцией; `--check` показывает «ОШИБКА», если сохранённый ключ не того формата.
5. `ui/keys_dialog.py` берёт правило из хранилища (имена `normalize_key`/`is_valid_base64_key` сохранены), в ошибке ввода называет причину; отказ хранилища по формату больше не выдаётся за «keyring недоступен».
6. `describe_key_state` говорит «формат неверный» — это видно в настройках.
7. Тесты: `tests/unit/infrastructure/test_gigachat_key_format.py` (29), +2 в `tests/ui/widgets/test_keys_dialog.py`.
8. Раскладка тестов: `all_test_files()` уважает `norecursedirs` из pytest.ini — карта слоёв перестала краснеть от venv, оставшегося в `tests/_tmp`.

## Грабли (актуальные)

- **K7 блокирует Inno Setup** — та же ошибка и на контрольном hello-world установщике. Не дефект скрипта.
- **«Запущено приложение → краснеют тесты»** — logs/app.log залочен, ротация падает PermissionError. Перед прогоном: Get-Process pythonw | Stop-Process -Force.
- **config/settings.json — рабочий файл оператора.** Тест, который читает его, ведёт себя по-разному на разных машинах. Эталон — config/settings.example.json.
- **from core.X import Y не поднимается простым реэкспортом** — нужна регистрация в sys.modules + атрибут пакета.
- **core.contracts — namespace-пакет, __init__.py туда нельзя:** приватные типы перестанут находиться.
- **lambda и functools.partial в connect запрещены** — цикл Python ↔ Qt → 0xC0000005.
- **Offscreen скрывает часть оконных багов** (кот не прятался вместе с окном только на нативной Windows). Поведение флагов проверять на живой платформе.
- **Модальный QMessageBox в offscreen роняет прогон** — подменять information/warning/critical в фикстуре.
- **pytest одним процессом на этой машине упирается в память** — гонять по слоям или частями.
- **Ключ GigaChat — только Base64** («Authorization key», пара client_id:client_secret). Ключи вида `sk-…` — это другие сервисы; сервер отвечает 400 «Can't decode 'Authorization' header». Проверка: `python set_key.py --check`, причина называется словами.
- **`tests/_tmp` не временна, а живёт годами** — в ней остаются venv (`video_tools`) с файлами `test_*.py` в site-packages. Счётчики раскладки берут `norecursedirs` из pytest.ini; чистить `tests/_tmp` от venv перед прогоном не обязательно, но память она занимает.
