**Фикс «attempt to write a readonly database» + пересборка exe (06.11.2026).**
Жалоба оператора: при сохранении — окно «Не удалось сохранить данные: attempt to write a readonly database». Причина класса: файл `contracts.db` (или его спутники `-wal`/`-shm`) получил атрибут «Только чтение» — после переезда данных в `%APPDATA%` в v1.4.1, копирования, переустановки или из-за антивируса; либо в папке данных нельзя создавать файлы. SQLite такую базу ОТКРЫВАЕТ (чтение работает), поэтому отказ виден только в момент сохранения — когда форма уже заполнена.
1. `db/write_access.py` (новый модуль пакета `db/`) — права на базу: `clear_readonly_files` снимает атрибут (`os.chmod(..., S_IWRITE)`) с базы и спутников ДО открытия; `directory_problem` проверяет создание файлов в папке данных настоящим файлом (ждать `-wal`); `probe_write` — проба записи настоящей транзакцией `CREATE TABLE` + `ROLLBACK` (в базе не остаётся ни таблицы, ни транзакции); `classify_error`/`readonly_message`/`locked_message`/`save_error_text` — понятный текст вместо сырого SQLite; `take_startup_problem` — причина для окна (одна на запуск).
2. `db/connection.py` — перед каждым `sqlite3.connect` снимается «только чтение»; на первом подключении к пути — проверка папки и проба записи. Отказ: `logger.error` с шагами + запоминание для окна; соединение не рвётся (читать можно). **Почему не `PRAGMA query_only`/`journal_mode`:** проверено пробой на этой машине (SQLite 3.50.4) — `query_only` отдаёт 0, `journal_mode=WAL` молчит, `BEGIN IMMEDIATE` проходит; ошибку `SQLITE_READONLY` даёт только реальная запись.
3. `main.py::_warn_if_database_readonly` — после создания `QApplication` показывает окно «База данных доступна только для чтения» с шагами: закрыть вторую копию программы, снять «Только чтение», исключения антивируса, права доступа. У `.exe` консоли нет — `logger.error` оператор не увидит.

## Грабли (актуальные)

- **«attempt to write a readonly database» — не повод менять SQL.** SQLite открывает файл с атрибутом «Только чтение» как read-only, и чтение работает: отказ виден только при сохранении. `PRAGMA query_only` на это НЕ реагирует (это настройка соединения, у нас 0), `PRAGMA journal_mode = WAL` молчит (база уже в WAL), `BEGIN IMMEDIATE` проходит. Настоящую ошибку даёт только реальная запись — проба `CREATE TABLE` + `ROLLBACK` (`db/write_access.py`). Атрибут снимать ДО `sqlite3.connect`: на открытом read-only дескрипторе chmod уже бесполезен.
- **Атрибут «только чтение» снимается у базы И у `-wal`/`-shm`,** и отдельно проверяется право создавать файлы в папке данных: без него SQLite не создаст журнал и упадёт тем же readonly. `os.access(..., W_OK)` на Windows видит атрибут «Только чтение», но НЕ видит ACL — запрет по правам ловится только пробой записи.
- **У `.exe` нет консоли:** `logger.error` оператор не увидит. Причину старта забирает `db/write_access.take_startup_problem()` и показывает окном `main.py::_warn_if_database_readonly` (одно окно на запуск).
- **Занятый файл журнала не должен ронять запуск.** `SafeRotatingFileHandler` уводит журнал в `%TEMP%\LogisticsContractor_fallback_logs\<pid>_<имя>`, при полном отказе — в stderr; не заменять его обратно на `RotatingFileHandler` без такой защиты.
- **SQLite `LOWER()` не понимает кириллицу** — сравнение адресов-артефактов импорта делается в Python через `casefold()`.
- **Прежний импорт салонов писал наименование в `address`.** Повторный импорт того же файла находит такие записи по имени/сырому адресу, переиспользует и чистит, дубли сливает; записи из других файлов не трогает.
- **K7 блокирует Inno Setup** — та же ошибка и на контрольном hello-world установщике. Не дефект скрипта. **05.11.2026 исключение:** `ISCC installer.iss` собрал установщик за 49 с (exit 0) — блокировка не постоянная, гадать по прошлому опыту нельзя, надо пробовать сборку заново.
- **«Запущено приложение → краснеют тесты»** — logs/app.log залочен, ротация падает PermissionError. Перед прогоном: Get-Process pythonw | Stop-Process -Force.
- **config/settings.json — рабочий файл оператора.** Тест, который читает его, ведёт себя по-разному на разных машинах. Эталон — config/settings.example.json.
- **from core.X import Y не поднимается простым реэкспортом** — нужна регистрация в sys.modules + атрибут пакета.
- **core.contracts — namespace-пакет, __init__.py туда нельзя:** приватные типы перестанут находиться.
- **lambda и functools.partial в connect запрещены** — цикл Python ↔ Qt → 0xC0000005.
- **Offscreen скрывает часть оконных багов** (кот не прятался вместе с окном только на нативной Windows). Поведение флагов проверять на живой платформе.
- **Модальный QMessageBox в offscreen роняет прогон** — подменять information/warning/critical в фикстуре.
- **pytest одним процессом на этой машине упирается в память** — гонять по слоям или частями.
- **Ключ GigaChat — только Base64** («Authorization key», пара client_id:client_secret). Ключи вида `sk-…` — это другие сервисы; сервер отвечает 400 «Can't decode 'Authorization' header». Проверка: `python set_key.py --check`, причина называется словами.
- **`tests/_tmp` не временна, а живёт годами** — в ней остаются venv (`video_tools`) с файлами `test_*.py` в site-packages. Счётчики раскладки берут `norecursedirs` из pytest.ini; чистить `tests/_tmp` от venv перед прогоном не обязательно, но память она занимает.
- **VIN может быть разрезан переносом строки.** При копировании из таблицы 17-й символ уезжает на отдельную строку («LMGAE3G58T100564 GS4» + «3»). `DataMapper.join_wrapped_vins` склеивает неполный токен 15–16 символов с продолжением из 1–2 символов; продолжение из двух символов — только цифры, иначе марка «S9» приклеилась бы к VIN. Цифры-переносы сами по себе машинами не становятся.
- **Реестр менеджера окон держит СЛАБУЮ ссылку** (`ui/windows/manager.py`): менеджер, созданный «на лету» и переданный в `register_window_manager`, сразу собирается сборщиком, и диалог связанных договоров его не видит. В тестах (и в main.py) на менеджер должна оставаться живая переменная.
- **K7 не даёт запускать свежесобранный exe с диска E:** — процесс стартует, но любая запись (`mkdir`, `icacls`, открытие `audit.log`) падает `PermissionError`, включая запись в `C:\`. Та же сборка, запущенная с C:, работает и проходит `--selftest`. Поэтому сборку проверять из C: (например, скопировать `dist\LogisticsContractor` в `C:\...`), а не из `E:\Programmy\...\dist`.
- **`Запуск программы.bat` — режим исходников; данные задаются `LOGISTICS_DATA_ROOT`.** Без него `core/data_paths.py` берёт `tests/_tmp/_appdata`, и база в bat «пустая» по сравнению с exe. Теперь bat выставляет `%APPDATA%\LogisticsContractor` — база, настройки, журналы и договоры общие с установленной программой.
