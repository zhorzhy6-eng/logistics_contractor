# Юридическая помощь оператору

> Пять уровней помощи: от проверки формы по нормам до юридического
> советника. Главное правило: **норма без источника не норма** —
> программа не выдумывает право и не даёт советов без ссылки на акт.

## Зачем это

Оператор готовит договоры перевозки, аренды и заявки. Ошибки в них стоят
денег: ставка НДС не та, срок оплаты не согласован, маршрут не указан.
Юрист на каждую форму не сядет, а правила — федеральные законы и приказы —
уже лежат в правовой базе программы (`data/knowledge/legal/`). Юридическая
помощь превращает эту базу в пять конкретных действий:

| Уровень | Что делает | Где в программе |
|---|---|---|
| 1. Проверка формы | Находит нарушения норм в заполненной форме | Кнопка «⚖» в панели Максимилиана, инструмент `check_contract_legal` |
| 2. Объяснение последствий | «Что будет, если…» — норма, последствия, что делать | Инструмент `explain_consequences` |
| 3. Подсказки | Замечание в панели, когда значение расходится с нормой | Панель Максимилиана (настройка `agent.legal_hints`) |
| 4. Советник | Ответ на юридический вопрос по нормам базы | Инструмент `legal_advice` |
| 5. Сравнение с типовым | Чем форма отличается от обычного бланка | Инструмент `compare_with_typical` |

## Правовая база проекта

Тексты актов лежат в `data/knowledge/legal/text/*.txt`, оригиналы — в
`original/`. Поиск по ним — RAG (`services/agent/tools/rag.py`):
эмбеддинги GigaChat, при их отсутствии — поиск по словам. Каждый фрагмент
несёт источник: акт, статью, номер, дату и ссылку на pravo.gov.ru.

Пополнение базы — кнопка «Скачать документ» в «Справка → Правовая база»
или инструмент `download_legal`. После скачивания индекс пересобирается.

**Важно:** если индекс не собран, юридические инструменты честно отвечают
«правовая база не собрана» и отправляют в «Настройки → Правовая база».
Пустой ответ поиска — это ответ «в базе нет», а не повод додумать норму.

## Каталог правил

Файл `data/knowledge/legal/rules.json`, читает `core/legal_rules.py`.
У каждого правила обязательны:

```json
{
  "title": "Ставка НДС",
  "rule_type": "exact",
  "field": "contract_tab.vat_rate",
  "value": 22,
  "severity": "error",
  "source": "НК РФ ст. 164 п. 3",
  "source_file": "2000-08-05-117-fz-nk-rf-ch-2.txt",
  "quote": "Налогообложение производится по налоговой ставке 22 процента…",
  "explanation": "Основная ставка НДС с 01.01.2026 — 22%.",
  "applies_to": ["perevozka", "formika", "logistiks_rus", "arenda_ts"]
}
```

* `rule_type`: `exact`, `max`, `min`, `required`, `validity` — проверка
  значения; `reference` — справочная норма (поле формы по ней не
  проверяется, она нужна для объяснений).
* `field` + `field_aliases`: где значение лежит в форме. У клиентских типов
  поле может называться иначе (`route_tab.route` вместо `contract_tab.route`).
* `quote` сверяется с `source_file` **дословно** тестом
  `tests/unit/core/test_legal_rules.py::test_quote_is_found_in_source_file`.
  Выдумать норму нельзя: сочинённой цитаты в тексте закона не найдётся.

### Какие правила есть сейчас

| Правило | Норма | Что проверяет |
|---|---|---|
| `vat_rate` | НК РФ ст. 164 п. 3 | ставка НДС = 22% («без НДС» допустимо) |
| `payment_days` | ГК РФ ст. 790 п. 1 | срок оплаты согласован (не пустой) |
| `route_required` | Правила перевозок грузов (ПП РФ № 2200), прил. № 6, п. 6 | маршрут заполнен |
| `driver_license_number` | УАТ ст. 10 ч. 1 | номер ВУ заполнен |
| `driver_license_valid` | КоАП РФ ст. 12.7 ч. 1; УАТ ст. 10 ч. 1 | срок ВУ не истёк |
| `pretension_reply_days` | УАТ ст. 40 ч. 1 | справочная: 30 дней на ответ на претензию |
| `transport_nakladnaya_required` | УАТ ст. 8 ч. 1, 3 | справочная: без ТН груз не принимается |
| `claim_period` | УАТ ст. 42 | справочная: срок исковой давности 1 год |
| `carrier_delay_penalty` | УАТ ст. 34 ч. 11 | справочная: 9% за сутки просрочки |

### Чего в каталоге НЕТ и почему

* **«Срок оплаты не больше 30 дней (УАТ ст. 34)»** — такой нормы в базе нет.
  УАТ ст. 34 говорит об ответственности, а срок оплаты отдан соглашению
  сторон (ГК РФ ст. 790 п. 1). Поэтому `payment_days` — требование
  «срок должен быть согласован», а типовое значение 30 дней живёт
  отдельно, в `data/knowledge/legal/templates/typical_*.json`.
* **«Пеня не меньше 0,1% в день»** — законом не установлена. УАТ ст. 34
  ч. 11 задаёт 9% провозной платы за сутки ПРОСРОЧКИ ДОСТАВКИ и потолок
  «не больше провозной платы», причём договор вправе установить иное.
  Норма включена справочным правилом.

## Уровень 1: проверка формы

`services/agent/tools/legal_check.py` → `check_contract_legal()`.

* Читает открытую форму (`get_data` вкладок) — **только чтение**;
* берёт правила по типу договора и проверяет то, у чего есть поле;
* поле отсутствует или значение пустое → правило в `skipped` с причиной,
  а не в нарушениях;
* у каждого нарушения есть `source`, `quote`, `current`, `required`.

Пример ответа:

```json
{
  "ok": true,
  "violations": [
    {"rule": "vat_rate", "title": "Ставка НДС", "severity": "error",
     "message": "Значение 20%, а по НК РФ ст. 164 п. 3 — 22%.",
     "source": "НК РФ ст. 164 п. 3", "field": "contract_tab.vat_rate",
     "current": "20%", "required": 22}
  ],
  "checked": 4,
  "skipped": [{"rule": "claim_period", "reason": "норма справочная…"}],
  "summary": "Найдено нарушений: 1 (ошибок 1, замечаний 0). Проверено правил: 4."
}
```

В интерфейсе — кнопка **«⚖»** в шапке панели Максимилиана: диалог
`ui/legal_check_dialog.py` показывает таблицу «важность — нарушение —
источник — комментарий», норму с цитатой и кнопку «Скопировать».

## Уровень 2: объяснение последствий

`explain_consequences(scenario, contract_type)` в `services/agent/tools/legal.py`.

1. RAG ищет нормы по ситуации (плюс тип договора в запросе).
2. Норм нет → «в правовой базе нет нормы по этому вопросу» (модель не
   вызывается вовсе — нечего пересказывать).
3. Нормы есть → GigaChat получает промпт `services/agent/core/prompts/legal_explain.txt`
   и нормы с цитатами; отвечает по трём пунктам: норма, последствия, что делать.
4. Для сложного вопроса (суд, спор, штраф, убытки, три и больше норм)
   в конце обязательно «Проверьте с юристом.».
5. Модель недоступна → ответ из цитат: честнее, чем правдоподобный текст.

## Уровень 3: подсказки в реальном времени

`services/agent/tools/legal_hints.py` + `services/agent/tools/proactivity.py`.

* Подсказка — **текст**, а не правка: форма не меняется.
* Повод — нарушение по полям `vat_rate`, `payment_days`, `route_required`,
  `driver_license_valid` (поля, которые оператор заполняет руками).
* **Пустое поле — не повод** (с 17.10.2026): подсказка говорит о норме, с
  которой разошлось ВВЕДЁННОЕ значение. «Поле не заполнено» — состояние
  формы, а не нарушение; за ним следят проверка по кнопке «⚖» и подсветка
  обязательных полей. Именно из-за этого панель, открытая вместе с
  программой, раньше начинала разговор с замечания про пустой маршрут.
* Первые 30 секунд после запуска программы подсказки молчат
  (`proactivity.STARTUP_QUIET_SECONDS`): оператор только вошёл в
  приложение, и замечание в этот момент — упрёк, а не помощь. Режим
  «Обучение» этой тишиной не глушится — его включает сам оператор.
* Не чаще одной в 300 секунд и без повторов (движок `SuggestionEngine`).
* Пишется в панель Максимилиана, только когда панель открыта и оператор
  не печатает (пауза тишины 2 секунды).
* Включается настройкой `agent.legal_hints` (по умолчанию `true`).
* Длина подсказки — до 400 символов (`LEGAL_HINT_MAX_CHARS`); длинный
  текст режется **по концу предложения**, а не по счёту символов, и совет
  «Проверьте.» сохраняется всегда.

Пример: «Ставка НДС: Значение 20%, а по НК РФ ст. 164 п. 3 — 22%. …
Проверьте.»

## Уровень 4: юридический советник

`legal_advice(question, contract_type)` в `legal.py`, промпт
`services/agent/core/prompts/legal_advisor.txt`.

Формат ответа: норма с дословной цитатой → источник → применимость →
«Проверьте с юристом.» для сложного вопроса.

Программа страхует ответ модели:

* нет источника в тексте → дописывается строка «Источники: …»;
* цитата переписана «своими словами» → прикладывается блок «Нормы
  дословно» с текстом акта;
* нормы не нашлись → «в базе нет».

## Уровень 5: сравнение с типовым

`services/agent/tools/legal_compare.py` → `compare_with_typical()`.
Типовые значения — `data/knowledge/legal/templates/typical_perevozka.json`,
`typical_arenda.json`.

**Это практика, а не норма права.** 30 дней оплаты и пеня 0,1% — условия
типового бланка; в файле прямо написано, что это практика, а норма
указывается только там, где она есть в базе (НДС). Поэтому расхождение
называется «расхождение с типовым», а не «нарушение закона».

---

## Что программа НЕ делает

* Не меняет форму по результатам проверки: исправляет оператор.
* Не придумывает нормы, статьи и штрафы. Нет нормы в базе — «в базе нет».
* Не даёт советов «как обойти закон» и не обещает исход спора.
* Не заменяет юриста: сложные вопросы заканчиваются «Проверьте с юристом.».
* Не отправляет ПДн в модель: диалоговый слой маскирует ФИО, телефоны,
  паспорта (`core/pseudonymizer.py`).

## Как проверить

```bash
pytest tests/unit/core/test_legal_rules.py -o addopts="" -q
pytest tests/unit/agent/test_legal_check.py -o addopts="" -q
pytest tests/unit/agent/test_legal_hints.py -o addopts="" -q
pytest tests/unit/agent/test_legal_advice.py -o addopts="" -q
pytest tests/unit/agent/test_legal_compare.py -o addopts="" -q
pytest tests/ui/widgets/test_legal_check_dialog.py -o addopts="" -q --basetemp=tests/_tmp/_pt
```

Вживую: открыть форму, заполнить ставку НДС 20% → нажать «⚖» → увидеть
нарушение со ссылкой на НК РФ; ввести 22% → проверка чистая.
