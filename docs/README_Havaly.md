# Хавалы — заявка на перевозку авто (Excel)

> Справка по одному типу договора. Общее состояние проекта —
> [`STATE.md`](STATE.md), правила работы — [`../AGENTS.md`](../AGENTS.md).

| Что | Значение |
|---|---|
| Пункт в списке типов | «Хавалы» |
| Ключ типа | `zayavka_excel` (`core/contracts/contract_types.py`) |
| Окно | `ui/windows/havaly/window.py` (`HavalyWindow`) |
| Бланк | `templates/shablon_havaly.xlsx` (лист `TDSheet`) |
| Готовый файл | `output/Заявка_Хавалы_<дата ISO>.xlsx` |
| Генератор | `core/contracts/zayavka/generator.py` (`ZayavkaExcelGenerator`) |

## 1. Что это

Заявка на перевозку автомобилей автовозом. Приходит от заказчика **одной
Excel-формой** «ЗАЯВКА на перевозку автомобилей» — это не договор и не DOCX,
а таблица:

* один лист, имя всегда `TDSheet` (требование заказчика);
* над таблицей строка «Дата заявки:»;
* таблица из **32 колонок** A…AF: «Номер Лота», «VIN», «Марка», «Модель»,
  «Город погрузки», «Пункт погрузки», «Город доставки», «Пункт разгрузки»,
  «Дилер», «Код дилера», «Наименование транспортной компании», «Марка
  Автовоза», «Цвет кабины», «Номер автовоза», «Марка прицепа», «Номер
  Прицепа», «Фамилия», «Имя», «Отчество», «Номер В/У», «Дата выдачи В/У»,
  «Серия Паспорта», «Номер Паспорта», «Кем выдан паспорт», «Дата выдачи
  паспорта», «Гражданство», «Дата Рождения», «Прописка», «Планируемая дата
  погрузки», «Время погрузки», «№ телефона водителя», «Ставка с НДС»;
* **одна строка таблицы — одна перевозимая машина**, строк данных не больше
  десяти;
* ниже таблицы блок сторон: «Заказчик» и «Перевозчик».

**Стороны фиксированы:** заказчик — «Сюрлогистик», перевозчик — «ООО
ТЕХНОЛОГИСТИКА». Они напечатаны в бланке, от заявки к заявке не меняются
и в схеме данных не редактируются
(`core/contracts/zayavka/generator.py::CUSTOMER_NAME` / `CARRIER_NAME`).

Общие сведения заявки (номер лота, маршрут, автовоз, прицеп, водитель, план
погрузки, ставка) в бланке **повторяются в каждой строке таблицы**. В данных
они хранятся один раз — в блоке `zayavka`; при заполнении генератор пишет их
во все строки, при чтении берёт из первой заполненной.

## 2. Основной сценарий: заказчик прислал .xlsx

1. Открыть файл заказчика в Excel и **скопировать содержимое формы**
   (шапку с датой и таблицу) в буфер обмена.
2. В программе выбрать тип **«Хавалы»** (селектор «Тип договора» в шапке).
3. На любой вкладке открыть панель «Распознавание данных», вставить текст
   (кнопка «Вставить из буфера») и нажать **«Распознать вкладку»**.
4. Ответ модели раскладывается по **всем шести вкладкам** сразу: дата и номер
   лота — «Заявка», машины — «Груз», города и пункты — «Маршрут», водитель —
   «Водитель», автовоз и прицеп — «ТС», ставка — «Стоимость». Пустые поля
   ответа уже введённые значения **не стирают**.
5. Проверить и поправить данные на вкладках. Число машин — строки таблицы
   на вкладке «Груз» (до 10).
6. Нажать **«Создать договор»** (кнопка есть и в шапке окна, и на каждой
   вкладке): валидатор показывает замечания — после подтверждения генератор
   собирает файл из нашего бланка и кладёт его в `output/`. Диалог успеха
   предлагает открыть папку.

**Важно про источник бланка.** Окно всегда собирает файл из **нашего**
бланка `templates/shablon_havaly.xlsx` (метод `generate`), а не из файла
заказчика. Файл заказчика — источник **данных** (через распознавание или
ручной ввод). Заполнить сам файл заказчика, сохранив его оформление, умеет
бэкенд — `ZayavkaExcelGenerator.fill_from_template(path, data, output_dir)`;
в интерфейсе отдельной кнопки для этого нет (см. § 8).

## 3. Ручное заполнение с нуля

Ничего распознавать не обязательно: заявка заполняется руками на тех же
шести вкладках — «Заявка», «Груз», «Маршрут», «Водитель», «ТС», «Стоимость».
Дата заявки по умолчанию — сегодняшняя, стороны показаны справочно
(поля только для чтения). Кнопка «Создать договор» работает одинаково:
сбор данных со всех вкладок → валидатор → генерация .xlsx.

| Вкладка | Что вводится | Ключи данных |
|---|---|---|
| Заявка | дата заявки, номер лота, стороны (справочно) | `date`, `lot_number`, `customer_name`, `carrier_name` |
| Груз | таблица машин (до 10 строк) | `vehicles`: `vin`, `brand`, `model`, `dealer`, `dealer_code` |
| Маршрут | города и пункты погрузки/разгрузки, план погрузки | `loading_city`, `loading_point`, `unloading_city`, `unloading_point`, `loading_plan_date`, `loading_plan_time` |
| Водитель | ФИО, В/У, паспорт, гражданство, дата рождения, прописка, телефон | `driver_*` (13 полей) |
| ТС | автовоз и прицеп | `tractor_brand`, `tractor_color`, `tractor_plate`, `trailer_brand`, `trailer_plate` |
| Стоимость | ставка с НДС, ставка НДС | `price_with_vat`, `vat_rate` |

Имена полей вкладок совпадают с ключами схемы промпта — раскладка
«вкладка → данные» ничего не переименовывает
(`ui/windows/havaly/data.py::collect_havaly_data`).

Кнопка **«Очистить форму»** чистит только ту вкладку, из которой нажата
(дата заявки возвращается на сегодня, стороны — к константам).

## 4. Ограничения типа

1. **`vat_rate` в бланк не пишется** — в форме нет ячейки для ставки НДС,
   есть только колонка «Ставка с НДС». Ключ входит в
   `UNMAPPED_ZAYAVKA_FIELDS` генератора: он собирается из вкладки
   «Стоимость» и виден в данных, но в файл не попадает. При чтении файла
   возвращается пустой строкой.
2. **Стороны фиксированы и не редактируются.** «Сюрлогистик» и «ООО
   ТЕХНОЛОГИСТИКА» напечатаны в бланке; на вкладках это поля только для
   чтения, в данных — всегда константы генератора.
3. **При 0 машин общие сведения в файл не попадают.** В бланке номер лота,
   маршрут, автовоз, водитель и ставка — это колонки таблицы, а не отдельные
   поля: нет ни одной строки машины — нет и места, куда их записать. Строки
   таблицы, оставшиеся без машин, при генерации удаляются
   (`core/contracts/zayavka/postprocess.py::TrimVehicleRowsStep`), поэтому в
   готовом файле остаётся только шапка и блок сторон. Валидатор об этом
   предупреждает, но создание файла не блокирует.
4. **Имя файла зависит ТОЛЬКО от даты заявки:**
   `output/Заявка_Хавалы_<дата ISO>.xlsx` (пример:
   `output/Заявка_Хавалы_2026-09-16.xlsx`). Номер лота, заказчик и число
   машин на имя не влияют; если дата не заполнена или не разбирается,
   подставляется сегодняшняя дата. **Повторная генерация за ту же дату
   перезаписывает файл — это норма типа:** заявка собирается заново из формы,
   отдельной версии документа не заводится.
5. **`_guard_same_file`: правка в тот же день в ту же папку отклоняется.**
   Если источник бланка и цель совпадают по пути (например,
   `fill_from_template` по файлу, который лежит в `output/` под тем же
   именем), генератор не сохраняет файл, а падает с
   `ZayavkaTemplateError`: присланный бланк не затирается. Лечится другой
   папкой вывода.

## 5. Распознавание

* Клиент — **GigaChat**, ключ в системном хранилище Windows
  (`core/secrets_store.py`); клиент создаётся лениво, при первом нажатии
  «Распознать вкладку».
* Промпт — **свой у типа**: `get_prompt("zayavka_excel")` возвращает текст
  из `core/prompts/havaly.py` и передаётся вторым аргументом
  `recognize_text`. Дефолтный системный промпт клиента здесь не подходит:
  у Хавалов своя схема ответа.
* Схема ответа — **два блока**: `zayavka` (30 плоских полей: дата, номер
  лота, маршрут, стороны, автовоз, прицеп, водитель, план погрузки, ставки)
  и `vehicles` (до 10 машин по пяти полям). Блоков `carrier`, `customer`,
  `contract`, `tractor`, `driver` в ответе нет.
* Промпт требует **не выдумывать** данные: пустое поле — пустая строка,
  VIN-заглушка («Vin по факту погрузки», «нет», прочерк) — пустой `vin`,
  машин больше десяти — берутся первые десять.
* Распознавание идёт в пуле потоков (`QThreadPool`), ход виден в статус-баре;
  устаревшая (отменённая) задача на форму не влияет.

## 6. Проверка данных перед сохранением

Валидатор типа ничего не блокирует: он показывает, что стоит дозаполнить,
а файл собирается независимо от отчёта.

* **Ошибки** (`report.errors`) бывают только на структурно непригодном
  файле: файл не открывается, в нём нет листа `TDSheet`, не найдена строка
  шапки (нет колонки «Номер Лота»).
* **Всё остальное — замечания** (`report.warnings`): машин больше 10 или ни
  одной; в строке есть марка/модель/дилер, а VIN пуст; ставка с НДС не
  заполнена; пусты маршрут, автовоз, прицеп или водитель; VIN не похож на
  стандартный (17 символов, без I, O, Q); даты и время не в формате бланка.

## 8. Что умеет бэкенд сверх окна

`ZayavkaExcelGenerator` работает в обе стороны с любым файлом этой формы:

* `read_template(path)` → `{"zayavka": {...}, "vehicles": [...]}` — читает
  наш бланк, файл заказчика или только что созданный файл;
* `generate(data, output_dir=None)` — заполняет наш бланк;
* `fill_from_template(path, data, output_dir=None)` — заполняет **присланный**
  файл, сохраняя его оформление: колонки ищутся по заголовкам шапки, поэтому
  их порядок в файле заказчика может быть любым, а лишние строки таблицы
  обрезаются.

При чтении и записи исходный файл не меняется: запись всегда идёт в новый
файл в папке вывода.

## 9. Логи

В логи попадают только имена полей, количества и длины: ни ФИО, ни VIN,
ни номеров документов, ни адресов, ни телефонов, ни сумм
(`core/contracts/zayavka/generator.py::_log_cell`,
`ui/windows/havaly/window.py::_log_recognition_result`).
