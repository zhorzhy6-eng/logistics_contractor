# Безопасная правка шаблонов

> **Шаблон не меняется молча. Никогда.** Правка идёт только через диалог
> подтверждения «было / стало», с резервной копией и проверкой после
> записи. Это не удобство, а правило: из шаблона печатаются договоры,
> и испорченный плейсхолдер обнаруживается уже на клиенте.

## Почему так строго

Шаблон заполняется docxtpl. В нём три вида разметки:

```
{{contract_number}}                подстановка значения
{%p if is_vat_free %} … {%p endif %}   условный блок на абзац
{% for vehicle in vehicles %} … {% endfor %}   цикл по строкам
```

Цена ошибки:

* опечатка внутри `{{ }}` — поле останется пустым или документ не соберётся;
* разорванная пара `{%p if %}` … `{%p endif %}` — падение при создании;
* удалённый или переставленный run — слетевшее оформление (шрифт, отступы);
* «НДС 20%» в тексте — договор 2026 года с неверной ставкой налога.

python-docx **не умеет** менять текст абзаца без потери оформления: текст
живёт в `run` — куске с одинаковым форматированием, и новый абзац создаётся
с нуля, не наследуя стили. Поэтому правка меняет текст только внутри
существующего run.

## Что умеет анализатор

`services/agent/tools/template_analyzer.py` → `analyze_template(path)`.
Работает с `.docx` (абзацы тела и ячеек таблиц) и `.xlsx` (значения ячеек).
**Только чтение** — ни байта в файл.

| Что находит | Поле результата |
|---|---|
| Плейсхолдеры: имя, как записан, сколько раз | `placeholders`, `placeholder_count` |
| Условные блоки и циклы, парность | `conditional_blocks`, `unclosed_tags`, `extra_closing_tags` |
| Абзацы, таблицы, стили | `paragraphs_count`, `tables_count`, `styles` |
| Устаревшие ставки НДС (20%, 18%) | `has_vat_20`, `outdated` |
| Понятные предупреждения | `warnings` |

Открыть анализ в интерфейсе: панель Максимилиана → кнопка **«📄»**
(`ui/template_tools_dialog.py`) или вопрос помощнику «проверь шаблон»
(инструмент `analyze_template`).

## Порядок правки

1. **Анализ.** `analyze_template` — понять, что в шаблоне есть и что не так.
2. **Предложение.** `propose_template_fix(path, issue)` — файл НЕ меняется;
   возвращает список изменений: `paragraph_index`, `run_index`, `old`, `new`,
   `has_placeholder`, `safe`, `reason`.
3. **Подтверждение.** `ui/template_diff_dialog.py` показывает каждое
   изменение отдельной строкой с флажком. Оператор отмечает нужные.
4. **Запись.** `apply_template_changes(path, changes, selected)`:
   анализ «до» → `.bak` → правка только отмеченного и безопасного.
5. **Проверка.** анализ «после» + `regressions(before, after)`.
6. **Откат.** Любая поломка → `restore_backup` (файл из `.bak`), оператор
   видит причину.

Из интерфейса всё это — окно «📄 Шаблоны»: выбрать бланк → «Предложить
правку» → «Применить выбранные» в диалоге.

---

## Правила безопасности

1. **Абзац с плейсхолдером не правится никогда.** Есть `{{…}}` или `{%…%}` —
   изменение получает `safe: false` и в список применения не попадает,
   даже если оператор поставит флажок.
2. **Текст, разбитый на несколько runs, не правится автоматически.** Найдено
   в одном run — можно; разбито — `safe: false` с причиной «текст разбит на
   несколько фрагментов оформления».
3. **Меняется только текст внутри существующего run.** Новые абзацы не
   создаются, стили не пересобираются.
4. **.bak создаётся ДО первой записи** и не перезаписывается второй правкой:
   это состояние «до всех правок».
5. **Применяется только отмеченное** (`selected`). Пустой выбор — отказ,
   файл не трогается.
6. **Файл изменился после предложения** — правка пропускается
   (`skipped`), а не применяется вслепую.
7. **Агент не применяет правки.** У инструментов только анализ и
   предложение; запись — исключительно через диалог подтверждения.

---

## Проверка после записи

`regressions(before, after)` сравнивает три вещи:

* **набор и кратность плейсхолдеров** — пропал, задвоился или появился;
* **парность условных блоков** — незакрытый `if`/`for` недопустим;
* **стили абзацев** — пропавший стиль значит переоформление текста.

Дополнительно анализатор проверяет, что файл открывается. Любое
расхождение → откат и список причин оператору.

---

## Откат

* Автоматически: если проверка не прошла или запись упала (файл занят,
  нет прав). `restore_backup(path)` копирует `.bak` обратно.
* Вручную: переименовать `шаблон.docx.bak` в `шаблон.docx` (или скопировать
  `.bak` поверх). В Windows шаблон должен быть закрыт в Word.
* `.bak` удалять не нужно: он не попадает в git (см. `.gitignore`) и не
  мешает docxtpl.

## Что делать, если шаблон уже сломан

1. Открыть анализ («📄» в панели или «проверь шаблон»).
2. Если анализ говорит «не закрыт блок» — правка автоматически не
   предлагается: такой абзац чинится руками в Word.
3. Если в шаблоне «НДС 20%» без плейсхолдеров и текст не разбит — кнопка
   «Предложить правку» предложит замену и покажет diff.
4. Если непонятно, что именно менять, — не менять. Спросить юриста и
   оператора: у правки шаблона нет «отмены» для уже напечатанных договоров.

## Как проверить

```bash
pytest tests/unit/agent/test_template_analyzer.py -o addopts="" -q
pytest tests/unit/agent/test_template_editor.py -o addopts="" -q
pytest tests/ui/widgets/test_template_diff_dialog.py -o addopts="" -q --basetemp=tests/_tmp/_pt
pytest tests/ui/widgets/test_template_tools_dialog.py -o addopts="" -q --basetemp=tests/_tmp/_pt2
```

Регресс боевых шаблонов: `tests/unit/agent/test_template_analyzer.py::test_real_project_template_is_whole`
— открывает `templates/shablon_ooo.docx` и требует, чтобы плейсхолдеры были
на месте, а блоки парными.
