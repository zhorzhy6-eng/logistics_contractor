## 1. Назначение

Настольное приложение (Python 3.14 + PyQt5 5.15.11, Windows) для подготовки
договоров перевозки, аренды ТС и заявок — пять типов документов.

Полный цикл: приём документов и текста из разных источников → извлечение
реквизитов (локально и через GigaChat) → ручная проверка → заполнение формы →
генерация DOCX/XLSX по шаблону → проверка по действующему законодательству РФ →
хранение истории и результатов в SQLite.

## 2. Ограничения

- GigaChat анализирует переданный текст, но не ищет изменения
  законодательства в интернете.
- Поиск новых публикаций выполняется отдельно через официальный портал
  `publication.pravo.gov.ru` (см. `tools/update_legal.py`,
  `tools/download_legal_pre2011.py`).
- LLM предлагает анализ и правки, но **не изменяет** шаблоны и договоры
  автоматически.
- Проверяются все три шаблона: ООО, ИП с НДС и ИП без НДС.
- Стек: Python 3.14, PyQt5 5.15.11, python-docx, docxtpl, openpyxl==3.1.5,
  requests, keyring, SQLite.

## 3. Главный принцип: ядро и края

**Ядро** — правила и логика. Не зависит от БД, внешних API и интерфейса.
**Края** — всё изменяемое: БД, внешние API, файловая система, секреты, UI.
Края заменяемы, контракты между ядром и краями не ломаются никогда.

Из этого следуют три правила раскладки:

1. Если модуль можно заменить, не трогая правила, — он на краю
   (`infrastructure/`, `services/`, `db/`, `ui/`).
2. Если модуль выражает правило — он в ядре (`core/`).
3. Новое добавляется расширением, а не переписыванием ядра.

### Публичная и приватная части

Клиентские типы договоров вынесены в **отдельный репозиторий**
`E:\Programmy\logistics_contractor_private`. Их окон, генераторов, промптов и
бланков в публичном репозитории нет.

Связывает части `core/private_path.py` (`attach_private_root()`): корень
приватной папки добавляется в начало `sys.path`, а `__path__` общих пакетов
(`core`, `core.agent`, `core.contracts`, `core.prompts`, `ui`, `ui.windows`,
`tools`) расширяется приватными папками — уже импортированных сразу,
импортируемых позже перехватчиком в `sys.meta_path`. Вызов стоит в `main.py`
и `tests/conftest.py` **до** первого импорта пакетов типов.

Чтобы это работало, `core/contracts` — пакет-пространство имён (своего
`__init__.py` у него нет). Приватной папки нет — программа штатно работает в
режиме «только Экспедиторство»: реестр изолирует сбой импорта каждого типа
(`ContractTypeRegistry.failures()`), промпты отдают `None`, список выбора
строится по зарегистрированным типам. Подробности и инструкция «как добавить
нового клиента» — в [`PRIVATE_MIGRATION.md`](PRIVATE_MIGRATION.md).

## 5. Потоки данных

**Распознавание документа.**
`ui/document_import_dialog.py` → `services/recognition/import_service.py`
(`DocumentImportService`) → `reader.py` (локальный текст) → при необходимости
`ocr.py` и GigaChat Vision → `fields.py` (локальные правила) → `recognizer.py`
(`DataMapper`, схема полей) → сравнение и перенос в форму. Переносится только
то, что распознано; поля, где источники противоречат друг другу, остаются
пустыми до ручной правки.

**Ассистент «Максимилиан».**
`ui/agent_widget.py` → `core/agent/agent.py` (цикл «сообщение → инструменты →
ответ», не больше `max_tool_steps` шагов) → `tools.py`, `analytics_tools.py`,
`proactivity_tools.py`, `legal_tools.py`, `dadata_tools.py` (инструменты над
`db/crud/*`) → `llm.py` → `core/pseudonymizer.py` (маскирование ПДн) →
`gigachat_client.py`. Оригиналы восстанавливаются в ответе.

**Генерация договора.**
Вкладки формы → `ContractData` (`core/data/contract_data.py`) →
`core/validation/validator.py` → `GeneratorFactory` →
`core/contracts/<тип>/generator.py` (`BaseContractGenerator` + шаги
постобработки) → DOCX/XLSX по шаблону → `output/<дата>/` → запись в SQLite.

**Правовая база.**
`tools/update_legal.py`, `tools/download_legal_pre2011.py` → `original/` +
`text/` → `core/legal_parser.py` → `core/legal_indexer.py` (векторный индекс;
при недоступности эмбеддингов GigaChat переключается на локальные вектора) →
инструменты агента и `ui/legal_base_dialog.py`.

## 6. Контракты и договорённости

### 6.1. Обратная совместимость путей

Модули переезжают, старые импорты продолжают работать. Механизм — в
`core/__init__.py`, и он состоит из **двух** частей, каждая обязательна:

1. **Реэкспорт имён** — работает `from core import parse_date`.
2. **Регистрация старых имён модулей в `sys.modules`** (`setdefault`, не
   присваивание) — работает `from core.dates import parse_date`.

Второй пункт не заменяется первым: `from core.dates import X` — это импорт
**подмодуля**, Python ищет файл `core/dates.py` и без регистрации в
`sys.modules` падает с `ModuleNotFoundError`.

Объект модуля при этом **один**: `core.recognizer is
services.recognition.recognizer` → `True`. Это не копия и не обёртка, поэтому
`isinstance`, пикинг и сравнение классов ведут себя как раньше.

Ловушка: статический импорт соседей внутри `core/__init__.py` ломает
**обратный** порядок импорта (новый путь первым). В общем прогоне pytest этого
не видно — `core` уже загружен `conftest.py`. Поэтому у каждого этапа есть
проба, запускающая оба режима в отдельных процессах
(`tools/check_stage2_aliases.py`).

### 6.2. Имена логгеров — часть контракта

`config/logging_config.py` настраивает только логгеры из
`APP_LOGGERS = ("core", "ui", "db", "config", "main", "qt")`. Логгер, выпавший
из этого списка, теряет обработчики и уровень. Поэтому при переезде модуля
имя логгера задаётся **явно** прежним именем (`core.gigachat_client`), а не
берётся из `__name__`. На имена логгеров опираются `caplog` в наборах тестов.

### 6.3. Логи без персональных данных

В логи не попадают: ключ и токен GigaChat, персональные данные (ФИО,
паспорта, адреса, телефоны), содержимое договоров. `@trace` фиксирует только
размеры, ключи и идентификаторы; сводки заполненности — только имена полей.
Изображения и распознанный текст документов в логи не пишутся.

### 6.4. Qt

- `lambda` в `connect` запрещены — получается цикл ссылок Python ↔ Qt,
  процесс падает при выходе (`0xC0000005`).
- Окна типов не закрываются крестиком, а прячутся; реальное закрытие —
  `force_close()`.
- Выход из offscreen-`main.py` — только через `main._do_exit`.

## 9. Риски

- Официальный REST API портала не подтверждён; каталог отдаёт CSV только за
  последние 90 дней.
- Актуальность набора и доступность портала из РФ требуют повторной проверки;
  `pravo.gov.ru` с рабочей машины недоступен (таймаут), старые акты берутся из
  банка документов Президента России (`kremlin.ru/acts/bank`).
- Полный текст акта может быть доступен только в PDF — нужен надёжный
  экстрактор.
- Доступность и стоимость GigaChat зависят от типа учётной записи и тарифа
  (эмбеддинги на текущем тарифе отвечают `402 Payment Required` — индексатор
  переключается на локальные вектора).
- LLM может ошибаться или галлюцинировать: юридическое заключение и любые
  изменения требуют проверки человеком.

## 10. Что не делаем

- Не редактируем шаблоны и договоры автоматически без подтверждения
  пользователя.
- Не парсим Гарант и КонсультантПлюс.
- Не используем GigaChat API для интернет-поиска.
- Не коммитим персональные данные; шаблоны (`templates/`) — только чтение.
- Не ломаем контракты между ядром и краями ради быстрого фикса.
