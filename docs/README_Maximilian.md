# Максимилиан — ИИ-ассистент внутри программы (версия 1)

> Справка по агенту: зачем он, что умеет, как устроен и где лежат его
> границы. Краткое описание — в [`../README.md`](../README.md), раздел
> «Максимилиан — ИИ-ассистент внутри программы».

## 1. Что это

**Максимилиан** — учёный кот (очки и лупа), ассистент-помощник логиста
прямо в программе. Он отвечает на вопросы про поля, ищет данные в
справочниках, подтягивает записи в форму и распознаёт документы.

Гибридный режим показа: **иконка в углу** + **выезжающая панель чата** +
опциональный **плавающий кот**. Всё это отключается одной галочкой
в настройках.

## 2. Что умеет (версия 1)

| Задача | Пример вопроса |
|---|---|
| Объяснить поле | «что такое ИНН?», «как заполнять код подразделения» |
| Найти в справочнике | «найди Иванова», «покажи перевозчиков с истекающим договором» |
| Подтянуть запись в форму | «заполни по ИНН», «подтяни водителя» |
| Распознать документ | «что в этом PDF» |

## 3. Чего не делает (границы версии 1)

* не создаёт договоры (только заполняет форму — договор создаёт оператор);
* не удаляет данные;
* не работает с деньгами (не считает суммы и не меняет ставки);
* не ходит в интернет за пределы GigaChat;
* не меняет настройки программы и не выполняет произвольный код.

Эти границы записаны и в системном промпте (`core/agent/prompts/maximilian.txt`),
и в коде: у агента просто нет инструментов удаления, создания договоров и
изменения настроек.

## 4. Как это выглядит

* **иконка** — маленький кот в шапке окна (правее селектора типа договора),
  тултип «Максимилиан — нажмите, чтобы открыть»;
* **панель** — 350 px справа, выезжает за 200 мс: аватар, имя и образ,
  история диалога, поле ввода (Enter — отправить, Shift+Enter — перенос
  строки), кнопка «Отправить», кнопки «⚙» (настройки агента) и «✕»;
* **плавающий кот** — 96 px в правом нижнем углу: моргает раз в 5–10 секунд,
  «думает» во время запроса, перетаскивается, по клику открывает панель;
* **горячая клавиша** — `Ctrl+M` по умолчанию.

## 5. Архитектура

```
                 ui/agent_widget.py  (AgentWidget)
                 ├── AgentIconButton      — иконка в углу
                 ├── AgentPanel           — панель диалога
                 │   └── CatAvatar        — аватар (ui/agent_avatar.py)
                 ├── FloatingCat          — плавающий кот (родитель — окно!)
                 ├── SuggestionEngine     — подсказки без вопроса (5 минут)
                 └── AgentWorker (QThread) ──► рабочий поток
                                                     │
                        core/agent/agent.py  (Agent) │
                        ├── prompt.py + prompts/maximilian.txt
                        ├── personas.py     — образ и тон
                        ├── tools.py        — ToolRegistry, 35 инструментов
                        │   ├── analytics_tools.py   — сводки, топы, сравнение
                        │   ├── proactivity_tools.py — что дальше, сроки
                        │   ├── context_tools.py     — что открыто
                        │   └── dadata_tools.py      — ЕГРЮЛ
                        ├── proactivity.py  — что обязательно и что дальше
                        ├── long_memory.py  — алиасы, привычки, исправления
                        ├── memory.py       — история (таблица agent_history)
                        └── llm.py (SafeChat) ──► GigaChatClient.complete_chat
                                                     │
                                              db/crud/*  (только чтение
                                              справочников; запись — в
                                              agent_history, agent_memory,
                                              agent_feedback)
```

Ядро (`core/agent/`) не зависит от PyQt: «окно» для инструментов — это
объект с вкладками (`get_data` / `fill_data`), поэтому ядро проверяется
тестами без поднятия интерфейса.

### Цикл одного вопроса

1. Оператор пишет сообщение → оно уходит в память диалога.
2. Из памяти помощника (`long_memory.recall`) отбираются TOP-5 релевантных
   записей — алиасы, привычки, исправления — и добавляются в промпт.
3. `SafeChat` маскирует персональные данные (`<<PERSON_1>>`, `<<PHONE_1>>`)
   и отправляет историю + системный промпт + описания инструментов в GigaChat.
4. Модель отвечает либо текстом (готово), либо вызовом инструмента.
5. Если это опасный инструмент (заполнение формы) — `AgentWidget` показывает
   диалог подтверждения; отказ оператора возвращается модели как «отменено».
6. Инструмент выполняется, результат уходит в историю ролью `tool`.
7. Шаги 3–6 повторяются, пока модель не ответит текстом или пока не
   сработает один из трёх предохранителей: лимит шагов
   (`max_tool_steps`, по умолчанию 20), общий таймаут запроса (120 с) или
   защита от зацикливания (три одинаковых вызова подряд без новых данных).
   Ответ на любой из них — человеческий: «Задача большая — не успел за один
   запрос. Давай по частям.» и выбор, с чего начать.
8. Плейсхолдеры в ответе восстанавливаются — оператор видит свои данные.
9. Если в фразе была явная просьба запомнить («запомни…», «всегда…») или
   исправление — факт уходит в память (значения с ПДн не записываются).

## 6. Инструменты (35)

Все инструменты возвращают `{"ok": true, "data": …}` или
`{"ok": false, "error": …}` и работают только через `db/crud/*` —
SQL в инструментах нет.

### Поиск (чтение, без подтверждения)

| Инструмент | Что делает |
|---|---|
| `search_driver` | ищет водителя по ФИО, телефону или паспорту |
| `search_carrier` | ищет перевозчика по названию, ИНН или ОГРН |
| `search_customer` | ищет заказчика |
| `search_vehicle` | ищет ТС по VIN, госномеру или марке (машины договоров и тягачи водителей) |
| `search_contract` | ищет договор по номеру, дате, маршруту или стороне |
| `list_expiring_contracts` | договоры, истекающие через N дней |

### Чтение формы (без подтверждения)

| Инструмент | Что делает |
|---|---|
| `get_current_form` | текущие значения полей открытой формы |
| `get_schema` | какие разделы и поля есть у типа договора |
| `validate_current_form` | проверка формы через `core/validation/validator.py` |

### Заполнение формы (требует подтверждения)

| Инструмент | Что делает |
|---|---|
| `fill_field` | заполнить одно поле |
| `fill_from_entity` | подтянуть запись из базы и показать набор полей (форму не меняет) |
| `fill_entity_fields` | заполнить форму этим набором (после подтверждения) |

### Документы

| Инструмент | Что делает |
|---|---|
| `recognize_document` | распознать файл через `services/recognition/import_service.py` |
| `apply_recognized_fields` | перенести распознанное в форму (с подтверждением) |

### Справочные

| Инструмент | Что делает |
|---|---|
| `explain_field` | объяснить поле и как его заполнять |
| `get_help` | общая справка по программе |

### Аналитика (часть 3, только чтение)

Числа считает SQL (`db/crud/analytics.py`), а не модель: инструменты
возвращают готовые значения и фразу `data.text`. Имена таблиц, колонок,
операций и фильтров берутся из белых списков, поэтому SQL от модели не
проходит, а значения уходят параметрами.

| Инструмент | Что делает |
|---|---|
| `aggregate_contracts` | сумма / среднее / максимум / минимум / количество: «средняя сумма с Ромашкой за 3 месяца» |
| `compare_periods` | сравнить месяцы и кварталы: «сравни октябрь с сентябрём» — два числа, разница и рост в процентах, разбивка по сторонам |
| `top_contractors` | топ-N: «топ-5 перевозчиков за октябрь» |
| `count_records` | сколько записей подходит под условия: «сколько водителей с истекающим ВУ» |
| `check_data_quality` | что не заполнено, где дубликаты, что просрочено |

Периоды понимаются по-русски: «октябрь», «октябрь 2026», «3 месяца»,
«этот квартал», «2026», «с 01.09.2026 по 30.09.2026». Поля тоже можно
называть словами: «сумма», «ВУ», «телефон», «госномер».

### Проактивность (часть 4, только чтение)

| Инструмент | Что делает |
|---|---|
| `suggest_next_field` | что логично заполнить в открытой форме дальше |
| `check_required` | какие обязательные поля пусты (по типам договоров) |
| `warn_expiring` | что истекает: ВУ водителей и договоры |
| `suggest_from_history` | что оператор обычно делает в этом месте формы |

Подсказки без вопроса показываются, только если в настройках включён пункт
«Подсказывать, чего не хватает в форме», и не чаще одной в
`proactive_interval` секунд (по умолчанию 300 — «не больше одной в 5
минут»). Подсказка появляется в открытой панели и только после паузы в
работе оператора.

## 7. Образы

Образ влияет **только** на аватар и тон ответов — набор инструментов, права
и правила безопасности одинаковы.

| Ключ | Название | Тон |
|---|---|---|
| `cat_scientist` | Учёный кот | «Я проверил…», «Интересно…», вдумчиво |
| `cat_logist` | Кот-логист | «Готово», «Поехали», быстро |
| `cat_keeper` | Кот-хранитель | «Всё в порядке», «Спокойно», неторопливо |
| `neutral` | Без образа | только факты |

Аватары нарисованы кодом (`ui/agent_avatar.py`, QPainter): не зависят от
темы, не требуют картинок в сборке и масштабируются на любой размер.

## 8. Безопасность

* **Маскирование ПДн.** Перед каждым запросом тексты оператора и результаты
  инструментов обезличиваются (`core/pseudonymizer.py`); маппинг живёт
  только на время одного вопроса и на диск не пишется.
* **Подтверждение опасных действий.** `fill_field`, `fill_entity_fields` и
  `apply_recognized_fields` помечены `requires_confirmation = True`. Без
  диалога подтверждения (например, агент вызван из скрипта) они не
  выполняются вовсе.
* **Лимиты.** `max_tool_steps = 20` вызовов на вопрос (верхняя граница
  настройки), `max_history = 20` сообщений, таймаут GigaChat — из общих
  настроек. Плюс два предохранителя поверх лимита: **общий таймаут запроса
  120 с** (`Agent.max_request_seconds`, проверяется перед каждым шагом) и
  **защита от зацикливания** (`REPEAT_LIMIT = 3`: три одинаковых вызова
  подряд без новых данных — стоп). Любой из трёх даёт оператору один и тот
  же человеческий ответ с выбором, с чего начать.
* **Логи.** В `logs/app.log` попадают имена инструментов и результат
  («ок» / текст ошибки), но не значения полей и не текст диалога.

## 9. История диалога и память

Таблица `agent_history` в `contracts.db`:

```sql
CREATE TABLE agent_history (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  session_id TEXT NOT NULL,
  role TEXT NOT NULL,          -- user | assistant | tool
  content TEXT NOT NULL,
  tool_name TEXT,              -- имя инструмента (роль tool)
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

Сессия — один запуск программы: новая сессия начинает историю заново.
Очистка — в настройках Максимилиана: «Очистить историю диалога» (текущая
сессия) и «Удалить прошлые сессии». Справочники, договоры и адреса эти
кнопки не трогают.

### Память помощника (часть 5)

Таблицы `agent_memory` (алиасы, привычки, исправления) и `agent_feedback`
(👍/👎 на ответы):

```sql
CREATE TABLE agent_memory (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  kind TEXT NOT NULL,          -- alias | habit | correction
  key TEXT NOT NULL,           -- «Ромашка»
  value TEXT NOT NULL,         -- «ООО «Ромашка»»
  source TEXT,                 -- откуда узнали
  hits INTEGER DEFAULT 0,      -- сколько раз пригодилось
  created_at TEXT, updated_at TEXT
);

CREATE TABLE agent_feedback (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  session_id TEXT, message_id INTEGER,
  rating INTEGER NOT NULL,     -- 1 (👍) или -1 (👎)
  comment TEXT, created_at TEXT
);
```

Как это работает:

* **Алиас** — «Ромашка» = ООО «Ромашка»: оператор называет коротко, а
  помощник ищет и заполняет полное имя.
* **Привычка** — «всегда НДС 20 % для Ромашки»: правило по умолчанию.
* **Исправление** — «ИНН с пробелами → нормализовать»: как исправлять
  значение, если оно пришло неверно.
* Перед каждым вопросом из памяти отбираются **TOP-5 релевантных** записей
  (совпадение в ключе весит больше, чем в значении) и добавляются в промпт
  отдельным блоком «ЧТО ТЫ ПОМНИШЬ». Вся память в промпт не уходит: контекст
  модели не резиновый.
* Запись — по явной просьбе («запомни…», «всегда…») или при исправлении.
  Значения с паспортом, телефоном, длинным числом (ИНН/ОГРН) и словом
  «пароль» **не запоминаются**: память уходит во внешний сервис.
* В настройках есть раздел **«Что Максимилиан помнит»**: список записей,
  удаление по одной и кнопка **«Забыть всё»**. Справочники и договоры она
  не затрагивает — у помощника своя таблица.

## 10. Настройки

`config/settings.json`, раздел `agent` (все ключи необязательны —
отсутствующие берутся из значений по умолчанию):

| Ключ | По умолчанию | Что делает |
|---|---|---|
| `enabled` | `true` | включён ли помощник |
| `name` | `"Максимилиан"` | **не настраивается**: имя зафиксировано, значение из файла игнорируется |
| `avatar` | `"cat_scientist"` | образ |
| `mode` | `"hybrid"` | `icon` / `panel` / `hybrid` |
| `show_floating` | `false` | плавающий кот (при `false` кот не создаётся вовсе) |
| `show_panel_on_start` | `false` | открывать панель при запуске |
| `hotkey` | `"Ctrl+M"` | горячая клавиша |
| `max_history` | `20` | сколько сообщений помнит агент |
| `max_tool_steps` | `20` | вызовов инструментов на вопрос (границы настройки — 1…20) |
| `proactive` | `false` | подсказывать без вопроса |
| `proactive_interval` | `300` | пауза между подсказками, секунды |

При `enabled: false` не показывается ничего: ни иконки, ни панели, ни кота,
горячая клавиша не срабатывает, история и память не загружаются, запросы к
GigaChat для агента не уходят.

**Имя помощника не меняется.** Оно задано константой
(`core/settings_service.py::AGENT_NAME`), поля ввода в диалоге настроек нет,
а значение из старого файла настроек приводится к «Максимилиан» при чтении.

## 12. Проба «четыре состояния»

`tests/_tmp/_agent_states.py` (в git не идёт) поднимает настоящее окно
`MainWindow` в offscreen-режиме, подставляет вместо GigaChat сценарий и
снимает четыре состояния: иконка → панель с диалогом → плавающий кот →
выключено. Скриншоты — в `tests/_tmp/_agent_screenshots/`.

Инструменты при этом настоящие: поиск идёт в отдельную базу в `tests/_tmp`,
подтверждение — настоящим диалогом, заполнение — настоящей формой.
Выдуман только ответ модели.
