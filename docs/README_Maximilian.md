# Максимилиан — ИИ-ассистент внутри программы (версия 1)

> Справка по агенту: зачем он, что умеет, как устроен и где лежат его
> границы. Краткое описание — в [`../README.md`](../README.md), раздел
> «Максимилиан — ИИ-ассистент внутри программы».

## 1. Что это

**Максимилиан** — учёный кот (очки и лупа), ассистент-помощник логиста
прямо в программе. Он отвечает на вопросы про поля, ищет данные в
справочниках, подтягивает записи в форму и распознаёт документы.

Гибридный режим показа: **иконка в углу** + **выезжающая панель чата** +
опциональный **плавающий кот**. Всё это отключается одной галочкой
в настройках.

## 2. Что умеет (версия 1)

| Задача | Пример вопроса |
|---|---|
| Объяснить поле | «что такое ИНН?», «как заполнять код подразделения» |
| Найти в справочнике | «найди Иванова», «покажи перевозчиков с истекающим договором» |
| Подтянуть запись в форму | «заполни по ИНН», «подтяни водителя» |
| Распознать документ | «что в этом PDF» |

## 3. Чего не делает (границы версии 1)

* не создаёт договоры (только заполняет форму — договор создаёт оператор);
* не удаляет данные;
* не работает с деньгами (не считает суммы и не меняет ставки);
* не ходит в интернет за пределы GigaChat;
* не меняет настройки программы и не выполняет произвольный код.

Эти границы записаны и в системном промпте (`core/agent/prompts/maximilian.txt`),
и в коде: у агента просто нет инструментов удаления, создания договоров и
изменения настроек.

## 4. Как это выглядит

* **иконка** — маленький кот в шапке окна (правее селектора типа договора),
  тултип «Максимилиан — нажмите, чтобы открыть»;
* **панель** — 350 px справа, выезжает за 200 мс: аватар, имя и образ,
  история диалога, поле ввода (Enter — отправить, Shift+Enter — перенос
  строки), кнопка «Отправить», кнопки «⚙» (настройки агента) и «✕»;
* **плавающий кот** — 96 px в правом нижнем углу: моргает раз в 5–10 секунд,
  «думает» во время запроса, перетаскивается, по клику открывает панель;
* **горячая клавиша** — `Ctrl+M` по умолчанию.

## 5. Архитектура

```
                 ui/agent_widget.py  (AgentWidget)
                 ├── AgentIconButton      — иконка в углу
                 ├── AgentPanel           — панель диалога
                 │   └── CatAvatar        — аватар (ui/agent_avatar.py)
                 ├── FloatingCat          — плавающий кот
                 ├── QShortcut            — горячая клавиша
                 └── AgentTask (QThreadPool) ──► рабочий поток
                                                     │
                        core/agent/agent.py  (Agent) │
                        ├── prompt.py + prompts/maximilian.txt
                        ├── personas.py     — образ и тон
                        ├── tools.py        — ToolRegistry, 16 инструментов
                        ├── memory.py       — история (таблица agent_history)
                        └── llm.py (SafeChat) ──► GigaChatClient.complete_chat
                                                     │
                                              db/crud/*  (только чтение
                                              справочников и запись
                                              в agent_history)
```

Ядро (`core/agent/`) не зависит от PyQt: «окно» для инструментов — это
объект с вкладками (`get_data` / `fill_data`), поэтому ядро проверяется
тестами без поднятия интерфейса.

### Цикл одного вопроса

1. Оператор пишет сообщение → оно уходит в память диалога.
2. `SafeChat` маскирует персональные данные (`<<PERSON_1>>`, `<<PHONE_1>>`)
   и отправляет историю + системный промпт + описания инструментов в GigaChat.
3. Модель отвечает либо текстом (готово), либо вызовом инструмента.
4. Если это опасный инструмент (заполнение формы) — `AgentWidget` показывает
   диалог подтверждения; отказ оператора возвращается модели как «отменено».
5. Инструмент выполняется, результат уходит в историю ролью `tool`.
6. Шаги 2–5 повторяются, пока модель не ответит текстом или пока не
   наберётся `max_tool_steps` (по умолчанию 5).
7. Плейсхолдеры в ответе восстанавливаются — оператор видит свои данные.

## 6. Инструменты (16)

Все инструменты возвращают `{"ok": true, "data": …}` или
`{"ok": false, "error": …}` и работают только через `db/crud/*` —
SQL в инструментах нет.

### Поиск (чтение, без подтверждения)

| Инструмент | Что делает |
|---|---|
| `search_driver` | ищет водителя по ФИО, телефону или паспорту |
| `search_carrier` | ищет перевозчика по названию, ИНН или ОГРН |
| `search_customer` | ищет заказчика |
| `search_vehicle` | ищет ТС по VIN, госномеру или марке (машины договоров и тягачи водителей) |
| `search_contract` | ищет договор по номеру, дате, маршруту или стороне |
| `list_expiring_contracts` | договоры, истекающие через N дней |

### Чтение формы (без подтверждения)

| Инструмент | Что делает |
|---|---|
| `get_current_form` | текущие значения полей открытой формы |
| `get_schema` | какие разделы и поля есть у типа договора |
| `validate_current_form` | проверка формы через `core/validator.py` |

### Заполнение формы (требует подтверждения)

| Инструмент | Что делает |
|---|---|
| `fill_field` | заполнить одно поле |
| `fill_from_entity` | подтянуть запись из базы и показать набор полей (форму не меняет) |
| `fill_entity_fields` | заполнить форму этим набором (после подтверждения) |

### Документы

| Инструмент | Что делает |
|---|---|
| `recognize_document` | распознать файл через `core/document_import_service.py` |
| `apply_recognized_fields` | перенести распознанное в форму (с подтверждением) |

### Справочные

| Инструмент | Что делает |
|---|---|
| `explain_field` | объяснить поле и как его заполнять |
| `get_help` | общая справка по программе |

## 7. Образы

Образ влияет **только** на аватар и тон ответов — набор инструментов, права
и правила безопасности одинаковы.

| Ключ | Название | Тон |
|---|---|---|
| `cat_scientist` | Учёный кот | «Я проверил…», «Интересно…», вдумчиво |
| `cat_logist` | Кот-логист | «Готово», «Поехали», быстро |
| `cat_keeper` | Кот-хранитель | «Всё в порядке», «Спокойно», неторопливо |
| `neutral` | Без образа | только факты |

Аватары нарисованы кодом (`ui/agent_avatar.py`, QPainter): не зависят от
темы, не требуют картинок в сборке и масштабируются на любой размер.

## 8. Безопасность

* **Маскирование ПДн.** Перед каждым запросом тексты оператора и результаты
  инструментов обезличиваются (`core/pseudonymizer.py`); маппинг живёт
  только на время одного вопроса и на диск не пишется.
* **Подтверждение опасных действий.** `fill_field`, `fill_entity_fields` и
  `apply_recognized_fields` помечены `requires_confirmation = True`. Без
  диалога подтверждения (например, агент вызван из скрипта) они не
  выполняются вовсе.
* **Лимиты.** `max_tool_steps = 5` вызовов на вопрос, `max_history = 20`
  сообщений, таймаут GigaChat — из общих настроек.
* **Логи.** В `logs/app.log` попадают имена инструментов и результат
  («ок» / текст ошибки), но не значения полей и не текст диалога.

## 9. История диалога

Таблица `agent_history` в `contracts.db`:

```sql
CREATE TABLE agent_history (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  session_id TEXT NOT NULL,
  role TEXT NOT NULL,          -- user | assistant | tool
  content TEXT NOT NULL,
  tool_name TEXT,              -- имя инструмента (роль tool)
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

Сессия — один запуск программы: новая сессия начинает историю заново.
Очистка — в настройках Максимилиана: «Очистить историю диалога» (текущая
сессия) и «Удалить прошлые сессии». Справочники, договоры и адреса эти
кнопки не трогают.

## 10. Настройки

`config/settings.json`, раздел `agent` (все ключи необязательны —
отсутствующие берутся из значений по умолчанию):

| Ключ | По умолчанию | Что делает |
|---|---|---|
| `enabled` | `true` | включён ли помощник |
| `name` | `"Максимилиан"` | подпись в панели |
| `avatar` | `"cat_scientist"` | образ |
| `mode` | `"hybrid"` | `icon` / `panel` / `hybrid` |
| `show_floating` | `false` | плавающий кот |
| `show_panel_on_start` | `false` | открывать панель при запуске |
| `hotkey` | `"Ctrl+M"` | горячая клавиша |
| `max_history` | `20` | сколько сообщений помнит агент |
| `max_tool_steps` | `5` | вызовов инструментов на вопрос |

При `enabled: false` не показывается ничего: ни иконки, ни панели, ни кота,
горячая клавиша не срабатывает, история не загружается и запросы к GigaChat
для агента не уходят.

## 11. Тесты

| Файл | Что проверяет |
|---|---|
| `tests/test_agent_tools.py` | 16 инструментов: формат ответа, поиск, заполнение, ошибки |
| `tests/test_agent_core.py` | цикл агента с мок-GigaChat, память, образы, промпт, маскирование |
| `tests/test_agent_settings.py` | чтение и запись раздела `agent`, дефолты, нормализация |
| `tests/test_agent_widget.py` | иконка, панель, плавающий кот, клавиша, режимы, выключение, подтверждение |
| `tests/test_agent_dialogs.py` | аватары (4 образа, мигание) и диалог настроек |

UI-тесты разделены на два файла осознанно: Qt-объекты (окна, панели, диалоги)
живут до конца процесса, и десятки таких тестов в одном файле роняют прогон
при выходе (0xC0000409). Разделение держит число одновременно существующих
виджетов небольшим.

## 12. Проба «четыре состояния»

`tests/_tmp/_agent_states.py` (в git не идёт) поднимает настоящее окно
`MainWindow` в offscreen-режиме, подставляет вместо GigaChat сценарий и
снимает четыре состояния: иконка → панель с диалогом → плавающий кот →
выключено. Скриншоты — в `tests/_tmp/_agent_screenshots/`.

Инструменты при этом настоящие: поиск идёт в отдельную базу в `tests/_tmp`,
подтверждение — настоящим диалогом, заполнение — настоящей формой.
Выдуман только ответ модели.
