# Как контрибьютить в logistics_contractor

Правила работы над проектом: для себя через месяц и для нового разработчика.
Файл дополняет [`AGENTS.md`](AGENTS.md) (правила ведения проекта) и не
заменяет его: при расхождении главнее `AGENTS.md`.

## Перед началом работы

1. Прочитай [`AGENTS.md`](AGENTS.md) — правила проекта, § 1–8.
2. Прочитай [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md) — карта проекта:
   ядро и края, дерево пакетов, потоки данных.
3. Прочитай [`docs/STATE.md`](docs/STATE.md) — текущее состояние: HEAD,
   числа тестов, что сделано и что осталось.
4. Если работаешь с клиентскими типами договоров — прочитай
   [`docs/PRIVATE_MIGRATION.md`](docs/PRIVATE_MIGRATION.md): их код лежит
   в отдельном приватном репозитории.

Если хотя бы один пункт не прочитан — не начинай: половина «странностей»
проекта объясняется именно этими четырьмя файлами.

## Установка окружения

```bat
pip install -r requirements.txt
pip install ruff
```

- **Требуется Python 3.14** (проверено на 3.14.4) и Windows: интерфейс
  PyQt5 и хранилище ключа (Windows Credential Manager) платформенные.
- `requirements.txt` — **единственный источник правды по зависимостям**.
  `pyproject.toml` содержит только метаданные проекта; его раздел
  `dependencies` намеренно пуст.
- Ключ GigaChat хранится не в файлах, а в системном хранилище:
  `python set_key.py`.

## Процесс разработки

1. Создай ветку:

   ```bat
   git checkout -b feature/название
   ```

2. Внеси изменения.
3. Прогони тесты **по слоям** (штатный способ с Этапа 7):

   ```bat
   pytest tests/unit/ -o addopts="" -q --basetemp=tests/_tmp/_pt_unit
   pytest tests/integration/ -o addopts="" -q --basetemp=tests/_tmp/_pt_int
   pytest tests/ui/ -o addopts="" -q --basetemp=tests/_tmp/_pt_ui
   ```

   Быстрый вариант — только то, что затронул:

   ```bat
   pytest tests/unit/contracts/ -o addopts="" -q --basetemp=tests/_tmp/_pt_one
   ```

4. Прогони линтер:

   ```bat
   ruff check .
   ```

5. Коммить с осмысленным сообщением (см. ниже).
6. Push:

   ```bat
   git push origin feature/название
   ```

### Обязательные ключи pytest — почему

| Ключ | Зачем |
|---|---|
| `-o addopts=""` | сбрасывает `-q` из `pytest.ini`, иначе сводка нечитаема |
| `--basetemp=tests/_tmp/...` | **обязателен:** `%TEMP%\pytest-of-Zhorzhy\pytest-current` бывает битым симлинком и роняет pytest |

Ещё три правила прогона:

- **Закрой запущенное приложение перед прогоном.** Иначе `PermissionError`
  на `logs/app.log` (файл занят).
- **Два pytest с общим `--basetemp` одновременно запускать нельзя.**
- **Полный набор одним процессом не гоняем:** pytest падает с `0xC0000409`
  (свойство окружения — PyQt5 на Python 3.14). С Этапа 7 это и не нужно:
  слои запускаются раздельно, `tests/ui/` проходит одним процессом.
  Разбор «кто уронил процесс» — `tools/run_tests_in_parts.py`.

Qt в тестах идёт offscreen: `os.environ.setdefault("QT_QPA_PLATFORM",
"offscreen")`.

## Стиль коммитов

Используем префиксы:

- `feat:` — новая функциональность
- `fix:` — исправление бага
- `docs:` — только документация
- `refactor:` — рефакторинг без изменения поведения
- `test:` — только тесты
- `chore:` — зависимости, конфиги, обвязка

Пример:

```
feat: добавлен экспорт договоров в Excel
```

Шаги рефакторинга нумеруются как в `docs/STATE.md`: `1.A:`, `1.B:`, …
(например, `1.F: .ruff.toml — линтер (минимальные правила F, E9)`).

## Перед коммитом

- [ ] Все тесты зелёные (unit, integration, ui) — или явно объяснено,
      какие падения предсуществующие.
- [ ] `ruff check .` без новых замечаний (базовый уровень — правила `F`
      и `E9` из [`.ruff.toml`](.ruff.toml)).
- [ ] `docs/STATE.md` обновлён, если изменилось состояние (§ 8 `AGENTS.md`).
- [ ] Комментарии в коде — **на русском**.
- [ ] Логи — **без ПДн** (только имена полей, количества, длины).
- [ ] Новый код покрыт тестами, и тест проверен **на баге** (временно
      вернуть старое поведение — тест должен покраснеть).
- [ ] В git не попали ПДн, база `*.db`, `logs/`, `output/`, `config/settings.json`.

## Что нельзя делать

- **Не коммитить ПДн** (ФИО, паспорта, адреса, телефоны) — включая
  скриншоты и выгрузки.
- **Не использовать `lambda` в `connect`** — цикл ссылок Python ↔ Qt даёт
  падение `0xC0000005` при выходе.
- **Не выходить из offscreen `main.py` через `app.quit()`** — только через
  `main._do_exit`.
- **Не запускать `tools/make_*.py`** — они перезаписывают шаблоны, а их
  SHA256 зафиксированы в тестах.
- **Не трогать** `core/contract_data.py`, `core/validator.py`,
  `core/pseudonymizer.py`, `core/contracts/{perevozka,formika,
  logistiks_rus,arenda_ts}/*` — сначала спросить владельца
  (`AGENTS.md` § 4 «Ask first»).
- **Не заводить `core/contracts/__init__.py`** — `core.contracts` обязан
  оставаться пакетом-пространством имён, иначе подпакеты клиентских типов
  из приватной части перестанут находиться.
- **Не удалять и не переименовывать `docs/STATE.md`** — только обновлять
  содержимое.
- **Не дублировать `[tool.pytest.ini_options]` в `pyproject.toml`** —
  `pytest.ini` остаётся источником правды для pytest.

## Правила проекта

- Границы «ядро / края»: ядро (`core/`) — правила и логика, без Qt, без БД,
  без сети; края (`ui/`, `db/`, `infrastructure/`, `services/`) — заменяемы.
  Контракты между ядром и краями не ломаем никогда.
- Новое добавляем расширением, а не переписыванием ядра.
- Старые пути модулей работают через алиасы (`core/private_path.py`):
  переезд файла не повод править всех потребителей, но и оставлять новый
  код на старом пути не нужно.
- Стиль работы и границы — [`AGENTS.md`](AGENTS.md) § 3 и § 4.

## Если что-то сломалось

1. Сначала диагностика: это баг, изменившиеся правила или ошибка фундамента?
2. Баг → чинить внутри, границы не трогать.
3. Эволюция → расширять, сохраняя совместимость.
4. Фундаментальная ошибка → перепроектировать, сохраняя контракты.
5. Если расхождение с заданием — **СТОП, доложить, не додумывать**
   (`AGENTS.md` § 3.4).
