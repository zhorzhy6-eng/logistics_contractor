# Синтетические документы — база регрессии распознавания

Артефакты стресс-теста распознавания документов: **зёрна** генератора и
**baseline** метрик. Оба файла содержат только числа и коммитятся в git.

> **Здесь нет персональных данных.** Ни ФИО, ни серий и номеров, ни адресов,
> ни реквизитов: в `seeds.json` — 1000 целых чисел, в `baseline.json` —
> recall / precision / F1. Сами документы и картинки собираются прогоном и
> лежат в `tests/_tmp/` (в git не идут). Правило — `AGENTS.md` § 4.

## Состав

| Файл | Что это |
|---|---|
| `seeds.json` | 1000 зёрен генератора + раскладка по видам, уровням качества и дефектам |
| `baseline.json` | метрики эталонного прогона: recall / precision / F1 по видам документов и уровням качества |

## Как это работает

1. **Зерно → сценарий.** `tools/make_synthetic_docs.py::build_values(rng, kind)`
   собирает данные документа (ФИО, серия, номер, реквизиты) из закрытых
   словарей модуля. Одно и то же зерно даёт один и тот же сценарий — на этом
   и держится регрессия.
2. **Шаблон → картинка.** `tools/make_doc_templates.py` описывает бланк:
   пропорции, порядок блоков, кегли. Значения подставляет генератор.
3. **Картинка → поля.** Локальный конвейер приложения:
   `core.document_reader` → `core.document_ocr` (Tesseract) →
   `core.document_import_service.extract_local_fields`.
4. **Поля → метрика.** `tools/synthetic_stress.py::score` сравнивает
   найденное с ground truth: recall (сколько полей нашли), precision
   (сколько найденного верно), F1.

## Команды

```bash
# 1. Пересобрать зёрна (нужно только при изменении плана раскладки)
python tools/run_regression.py --write-seeds

# 2. Полный прогон 1000 сценариев и запись baseline (минуты)
python tools/run_regression.py --write-baseline

# 3. Повторный прогон и сравнение с baseline — ЭТО И ЕСТЬ РЕГРЕССИЯ
python tools/run_regression.py
python tools/run_regression.py --sample 50      # по 50 документов на вид
python tools/run_regression.py --tolerance 0.03 # допуск падения recall

# 4. Отдельно: локальный прогон по уже собранным картинкам
python tools/make_synthetic_docs.py             # 1000 картинок + ground truth
python tools/synthetic_stress.py synthetic       # метрики по ним
python tools/synthetic_stress.py gigachat        # ≤25 запросов, только синтетика
```

Инструмент возвращает код 1, если recall упал больше допуска — этим и
проверяется регрессия.

## Раскладка покрытия

| Вид документа | Сценариев |
|---|---:|
| Паспорт РФ | 300 |
| Водительское удостоверение | 200 |
| Банковские реквизиты | 200 |
| ИНН / ОГРН | 100 |
| ПТС / СТС | 100 |
| Заявка (свободная запись) | 100 |

| Уровень качества | Сценариев | Что делается с картинкой |
|---|---:|---|
| `ideal` | 100 | ничего |
| `good` | 200 | поворот 1–3°, яркость ±3 % |
| `medium` | 300 | поворот 5–8°, размытие, яркость ±10 % |
| `poor` | 250 | поворот 10–15°, размытие, шум, яркость ±30 % |
| `very_poor` | 150 | всё вместе + перспектива, блик, обрезка |

Дополнительные дефекты «недописанных букв»: обрезанная буква (100),
подмена похожих символов О→0, З→3, В→8 и латинских двойников (100),
двойная экспозиция (80), стёртые буквы (100).

## Что делать, если baseline «поехал»

1. Посмотреть, где именно упало:
   `python tools/run_regression.py` печатает расхождения по видам и уровням.
2. Разобрать конкретные сценарии: `tests/_tmp/synthetic_docs/local_details.json`
   хранит результат по каждому номеру (`missed` / `wrong` поля).
3. Если падение — СЛЕДСТВИЕ осознанной правки (например, разбор стал
   строже и перестал угадывать битые цифры), обновить baseline:
   `python tools/run_regression.py --write-baseline` — и объяснить причину
   в `docs/STATE.md`.
4. Если падение — неожиданное, искать причину, а не обновлять baseline.

## Чего здесь делать НЕЛЬЗЯ

- Класть в эту папку картинки документов или их фрагменты: папка идёт в git.
- Класть в `seeds.json` и `baseline.json` значения полей — даже
  синтетические: файлы читают как «только числа», и это проверяется тестами
  `tests/test_synthetic_docs_regression.py`.
- Использовать реальные документы оператора в прогонах, которые пишут
  картинки на диск: реальные документы читаются только «на месте»
  (`tools/synthetic_stress.py real`) и наружу отдают одни числа.
