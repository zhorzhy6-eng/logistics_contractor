# Changelog

Все значимые изменения проекта. Формат основан на
[Keep a Changelog](https://keepachangelog.com/ru/1.1.0/), версии — по
[Semantic Versioning](https://semver.org/lang/ru/).

> **О датах и версиях.** Версии проставлены по этапам работы, а даты взяты
> из истории git (`git log --date=short`), а не придуманы: проект
> разрабатывается с 27.09.2026. Записи идут от новой к старой, поэтому
> версия `1.2.0` (15.10.2026) стоит выше `1.1.0` (13.10.2026) — работа над
> правовой базой началась раньше, но закрылась позже.
> `[Unreleased]` — обвязка проекта (Этап 8 рефакторинга): она станет
> следующей версией, когда этап закроется. Подробный журнал тех же
> событий — в разделах «Что сделано» файла
> [`docs/STATE.md`](docs/STATE.md).

## [1.4.1] — 2026-10-18

Данные пользователя переехали из папки программы в `%APPDATA%`.
**Обновление больше не может потерять договоры:** установщик папку данных
не трогает.

### Добавлено

- `core/data_paths.py` — единая точка путей к данным: `contracts.db`,
  `config/settings.json`, `logs/`, `output/`. В `.exe` —
  `%APPDATA%\LogisticsContractor`, в разработке — `tests/_tmp/_appdata`,
  переопределяется переменной `LOGISTICS_DATA_ROOT`.
- Миграция старых данных (`data_paths.migrate_old_data`): при первом
  запуске база и настройки из папки программы **копируются** в папку
  данных. Старые файлы не удаляются.
- `rebuild.ps1` — пересборка exe и установщика одной командой
  (тесты → PyInstaller → Inno Setup).
- `README_УСТАНОВКА.md` — разделы «Что и где лежит» и «Обновление
  программы».

### Изменено

- База, настройки, журналы и готовые договоры больше не пишутся рядом с
  программой — они в `%APPDATA%\LogisticsContractor`. Раньше папку
  программы при обновлении заменяли, и данные пропадали.
- `installer.iss` — версия 1.4.1; данные пользователя вне установщика,
  `[UninstallDelete]` их не касается.

## [1.4.0] — 2026-10-16

Рефакторинг: раскладка кода по слоям. **Поведение приложения не менялось —
менялись только адреса модулей и файлов.** Обратная совместимость старых
путей держится алиасами `sys.modules` + атрибутами пакетов
(`core/private_path.py::register_module_alias`).

### Добавлено

- `infrastructure/` — клиенты GigaChat и DaData, хранилище секретов, TLS.
- `infrastructure/api/gigachat.py`, `infrastructure/api/dadata.py`,
  `infrastructure/api/tls.py`, `infrastructure/secrets/store.py`.
- `core/utils/json_text.py` — разбор JSON-ответов модели.
- Тесты раскладки: `tests/unit/core/test_core_layout.py`,
  `test_services_layout.py`, `test_infrastructure_layout.py`,
  `test_contracts_base_layout.py`, `test_agent_layout.py`,
  `tests/ui/main_window/test_ui_main_window_layout.py`,
  `tests/test_tests_layout.py` (320 проверок).
- Пробы обратной совместимости: `tools/check_stage2_aliases.py` …
  `tools/check_stage5_aliases.py` (режимы `old`/`new`).

### Изменено

- Распознавание документов переехало в `services/recognition/`
  (было `core/document_reader.py`, `document_ocr.py`, `document_fields.py`,
  `recognizer.py`, `document_import_service.py`).
- Агент «Максимилиан» переехал в `services/agent/` тремя группами:
  `core/` (ядро), `tools/` (11 инструментов), `persona/` (личность).
  В `core/agent/` остались shim и читаемая файлом таблица слов `words.py`.
- `core/contracts/base_generator.py` (1128 строк, один класс на шесть
  ответственностей) разбит на пакет `core/contracts/base/` из семи модулей.
  Все 54 метода прежнего класса на месте; переехавшие остались тонкими
  делегатами с прежними подписями.
- `ui/main_window.py` (2136 строк) разобран на пакет `ui/main_window/`
  из 11 модулей + `__init__.py` (девять миксинов). Публичный API класса
  и модуля сохранён полностью — 86 имён прежнего модуля реэкспортированы.
- Тесты разложены по слоям: `tests/unit/` (57 файлов),
  `tests/integration/` (25), `tests/ui/` (60). Логика тестов не менялась.
- `docs/ARCHITECTURE.md` создан (перенос `PLAN.md`), `PLAN.md` удалён —
  две дорожные карты противоречили друг другу.
- `AGENTS.md` § 4 и § 6 приведены к фактическим путям (правил пользователь).

### Исправлено

- Падение pytest `0xC0000409` при прогоне всего набора одним процессом —
  снято группировкой по слоям: `tests/ui/` (1687 тестов) проходит одним
  процессом за ~18 минут.
- Регрессия переезда в `tests/ui/tabs/test_recognition_bank_name.py`:
  локальная фикстура `templates_dir` считала корень проекта от `__file__`
  и после переезда вела в `tests/ui/templates`. Фикстура удалена, тест
  берёт общую из `tests/conftest.py`.
- Регрессия разбиения `ui/main_window.py`: пропало имя модуля `_action_icon`
  (у прежнего модуля было два публичных API — класс и имена модуля). Закрыто
  реэкспортом всех 86 имён и тестом со сверкой по `git show 8362a67:…`.
- Подмена функции через атрибут ПАКЕТА (`monkeypatch.setattr(ui.main_window,
  …)`) не перехватывала вызов — тест был зелёным, ничего не проверяя.
  Подмена переведена на модуль-владелец, тест проверен на баге.
- `default_output_dir()` стал считать корень проекта от нового места файла
  (`parents[3]`) — иначе договоры падали бы в `core/contracts/output/`.
- `tutorial.project_root()` — четвёртый `dirname` после переезда; ошибка была
  бы тихой (список папок инструкций просто оказался бы пустым).
- 60 файлов тестов переведены с `Path(__file__).parent.parent` на поиск
  корня по маркеру `pytest.ini` — переезд ломал не импорты, а пути к файлам.

### Удалено

- `core/contract_generator.py` (раскладка Этапа 4), прежние одиночные модули
  распознавания и агента, `ui/main_window.py` и `PLAN.md`.
- Локальная копия фикстуры `templates_dir` в тесте распознавания.

## [1.3.0] — 2026-10-16

Разделение проекта на публичную и приватную части.

### Добавлено

- Приватный репозиторий `logistics_contractor_private` — клиентские типы
  договоров (шаблоны, промпты, окна, инструкции, тесты, инструменты сборки).
- `core/private_path.py` — `attach_private_root()`: приватный корень
  добавляется в `sys.path`, а `__path__` общих пакетов расширяется приватными
  папками; `register_module_alias()` — единая регистрация алиасов.
- `docs/PRIVATE_MIGRATION.md` — устройство разделения и инструкция «как
  добавить нового клиента».
- Швы разделения: `picker_labels.py`, `mirror_targets.py`, `labels.py`
  (приватные), поиск промптов и шаблонов по ключу типа.

### Изменено

- `core/contracts` стал пакетом-пространством имён (`__init__.py` удалён) —
  иначе обычный пакет «выигрывал» поиск у приватной папки и подпакеты
  клиентских типов не находились.
- Публичное ядро работает без приватной части — в режиме «только
  Экспедиторство».

### Исправлено

- История публичного репозитория очищена `git filter-repo` в два прохода:
  удаление приватных путей, правка сообщений коммитов, замена названий
  клиентов во всех файлах истории. Поиск названий по истории (`git log
  --all -S`) — пусто; `git fsck` чист; `.git` уменьшился с 224 до 37 МБ.

### Удалено

- Локальные снимки `refs/codex/*` с реальными ПДн (на GitHub их не было).

## [1.0.0] — 2026-10-10

Первая рабочая версия: подготовка договоров перевозки, аренды и заявок
(5 типов), распознавание документов, обезличивание ПДн.

### Добавлено

- Приложение PyQt5: вставка текста → распознавание через GigaChat →
  заполнение вкладок → генерация DOCX по шаблону → база SQLite.

  `ContractTypeRegistry`, `GeneratorFactory`, `ValidatorFactory`).
- Распознавание документов: читалка, OCR, разбор полей, импорт
  (`core/document_*.py`, `core/recognizer.py`).
- Маскирование ПДн перед отправкой в облако (`core/pseudonymizer.py`):
  регулярки + опциональный слой Natasha; логи без ПДн (`core/audit.py`,
  `core/trace.py`).
- Хранение ключа GigaChat в Windows Credential Manager
  (`infrastructure/secrets/store.py`, `set_key.py`).
- База SQLite: справочники, договоры, аналитика (`db/`).
- Инфраструктура типов договоров (Этапы 1, 2C, 3.1.A) — 03.10.2026.

  оригинал с ПДн — локально в `data/private/`.

- Предоплата: поле в интерфейсе и разбивка оплаты (08.10.2026).
- Справочник контрагентов вынесен из фасада базы (`db/crud/`, 09.10.2026).

  динамические стороны в шаблонах Экспедиторства (09.10.2026).

- Сохранение перевозчика.
- Закрытие окна `0xC0000005`: запрет `lambda` в `connect` (цикл ссылок
  Python ↔ Qt), явный выход процессом (`main._finish_process`).
